The chair reviewed platform boundaries; two independent specialists reviewed author intent/native science and data/output/handoffs, followed by explicit challenge and rebuttal. This report does not review CRISPRidentify itself. No scientific source, runtime, reference collection or production service was changed.

## Author intent and scientific fidelity

The release lock explicitly describes source-bound repeat structure and local context as descriptive evidence (`tools/tools.lock.json:68–75`). Integration invokes an isolated CLI, uses both DNA orientations or forward-only supplied RNA, and binds context runs to detector reports (`Integration/crispr_integration/repeats.py:25–74`). This appropriately avoids interpreting lower free energy as transcription-direction evidence.

The native package requires ViennaRNA 2.7.0, explicitly loads Turner2004 parameters, snapshots both energy and Boltzmann tables, and substitutes these owned tables into each fold compound (`tools/CRISPRrepeat/src/crisprrepeat/folding.py:57–111`). It fixes temperature, dangles, salt, minimum loop, GU policy and other model details rather than inheriting incidental process defaults. Runtime provisioning verifies distribution/binding versions and hashes the native extension; release assembly rechecks that identity (`scripts/provision_tools.py:138–160`; `scripts/manage_release.py:132–149`). Fresh native tests exercised interleaved settings and later replacement of process-global parameter tables.

Isolated folding returns MFE structure, ensemble energy and complete nonzero pair marginals. Local context uses window-averaged pair and single-base unpaired probabilities, preserving their different semantics (`folding.py:113–217`). Local accessibility must not be reconstructed as one minus a sum of independently averaged pair entries. The [ViennaRNA window API](https://viennarna.readthedocs.io/en/latest/partfunc/window.html) documents these separate quantities.

Detector intervals are converted from one-based inclusive to zero-based half-open coordinates, with original-sequence reconstruction and bounded array/repeat lengths (`tools/CRISPRrepeat/src/crisprrepeat/inputs.py:138–214`). Reverse context offsets use `array.end − repeat.end`; DNA alternatives remain separate, while RNA is supplied transcriptional sequence (`tools/CRISPRrepeat/src/crisprrepeat/analysis.py:32–41,66–89,100–136`). Ambiguous inputs, absent context, absent motif pairs and motifs beyond local span retain explicit unsupported reasons and null comparisons (`folding.py:220–249`). Array boundaries are analysis boundaries, not demonstrated transcript endpoints.

The [Reimann et al. study](https://academic.oup.com/nar/article/45/2/915/2953300) used particular transcripts, an older ViennaRNA version and different folding/motif choices. Current W150 local settings and isolated-MFE motif hypotheses are intentional. The repository preserves a cleaved low-support counterexample and distinguishes selected numerical regressions from biological accuracy (`tools/CRISPRrepeat/docs/REIMANN_REPRODUCTION.md:60–109`; `tests/test_published_reimann.py:41–83` within that checkout). No universal cleavage prediction or exact historical score reproduction is established.

## Required data and worthwhile extensions

The required background consists of thermodynamic tables supplied by the pinned dependency, not a CRISPR catalogue. Public reports deliberately require `reference_not_configured` and unsupported classifications (`backend/src/crispr_web/execution/validation_repeats.py:445–459`). That is an explicit scope boundary rather than a failed installation.

Standalone optional retrieval accepts a frozen, provenance-bearing reference document with sequence hashes, accession/evidence origins, 1–1000 entries and a bounded hit report (`tools/CRISPRrepeat/src/crisprrepeat/references.py:70–111,145–157`). Increasing this collection could broaden inspectable similarity matches. It cannot improve Turner parameters, establish homologous families automatically, or turn nearest neighbors into calibrated subtype/processing predictions. Any proposed expansion needs compatible DNA representation, deduplication preserving origins, licensing, immutable release identity, bounded indexing and measured retrieval benefit. Existing CRISPRmap/RepeatTyper workflows already address complementary reference/type questions; do not create a live database dependency here.

For a broader biological claim, prioritize independent processing experiments with exact RNA fragments, assay conditions, experimentally supported outcomes and known family/locus provenance. Evaluation should separate homologues, loci and studies, retain negative/counterexamples, and compare against isolated-fold and composition baselines. This is future scientific evaluation, not an automatic dataset or model update (`tools/CRISPRrepeat/docs/SCIENCE.md:3–23`).

## Output and downstream contracts

The preview is limited to 20 instance/orientation records and 700 kB; competing outside-repeat pairs retain full counts and explicit truncation flags (`backend/src/crispr_web/summaries/repeats.py:16–61`). Complete JSON, TSV, RNA FASTA and isolated dot-bracket exports come from the independently validated report, not the preview (`backend/src/crispr_web/publication/repeats.py:9–74`). Compact output preserves every defined instance, context and consensus-fold relationship while deduplicating fold records; dense probability/accessibility arrays deliberately remain detailed artifacts (`backend/src/crispr_web/publication/compact/repeats.py:13–80`).

The frontend states that DNA orientations are alternatives, energy/support is descriptive, local context is window-based, and missing classifications remain unsupported (`frontend/src/components/results/repeats/RepeatResults.vue:38–111`; `RepeatInstance.vue:65–108`). These qualifications prevent stronger biological interpretations. No demonstrated defect warrants removing them wholesale.

Context mode exports source-forward `repeats.json`, `spacers.json` and `arrays.json` with verified origins (`backend/src/crispr_web/publication/sequence_ports.py:115–143`; `array_data.py:149–220`). These support existing repeat analysis/reference/type and spacer/array workflows. Their origin coordinates are one-based inclusive, unlike fold coordinates; consumers must convert explicitly. They represent detector-derived observations, not proof supplied by folding.

For isolated `repeats`, `input-sequences.json` replays input (`sequence_ports.py:90–105`); `result.json` is evidence, not a submission port. Automatic RNAalifold routing would be scientifically unsafe: the comparative workflow requires asserted homology, explicitly supplied orientation/boundaries, 2–50 records, at least two distinct sequences and 30–500 unambiguous bases (`Integration/crispr_integration/rna_family.py:10–43`). Repeat folding allows shorter inputs and two DNA hypotheses. The [RNAalifold tutorial](https://www.tbi.univie.ac.at/RNA/ViennaRNA/doc/html/tutorial/RNAalifold.html) describes comparative folding of related aligned sequences. A curated subset could qualify; duplicated repeat copies, unrelated arrays or paired forward/reverse alternatives do not establish the prerequisites.

## Deliberation and adjudication

**Impossible probabilities.** The chair challenged both validators by inserting `[0,1,0.005]` into a frozen isolated report, representing adjacent GG, and subtracting 0.005 from each affected unpaired value. Integration accepted it and backend returned `completed`. A separate context probe inserted an adjacent CG probability and likewise passed. Probability gates currently validate bounds, uniqueness, numeric ranges and selected arithmetic; canonical/minimum-loop checks apply only to MFE pairs (`Integration/crispr_integration/repeat_validation.py:39–55,77–104`; `backend/src/crispr_web/execution/validation_repeats.py:29–105`).

The science reviewer challenged blanket “RNA validity” checks. Resolution: for this explicitly recorded model, every positive pair must have `j−i ≥ 4` and AU/UA/GC/CG/GU/UG identity in the oriented RNA. Retain valid GU closures. Do not reject crossing marginal entries, normalize local row sums, or claim `noLP` removes every isolated pair from every ensemble structure. The [RNAplfold manual](https://www.tbi.univie.ac.at/RNA/ViennaRNA/doc/html/man/RNAplfold.html) explains the partition-function `noLP` limitation. This is a demonstrated acceptance defect, **not evidence that honest pinned ViennaRNA emits impossible pairs**.

**Span disagreement.** Current online documentation is 2.7.2 and uses wording that suggested an off-by-one risk. Fresh installed-2.7.0 probes admitted `(0,5)` in `GAAAAC` only at span ≥6, and `(0,6)` in `GAAAAAC` only at span ≥7. The council retained the implemented endpoint-inclusive policy.

**Compact provenance proposal rejected.** Specialists initially proposed adding engine version/cutoff to compact output because those fields are absent. The chair reconsidered after the orchestration review cited `docs/module-results.md:86–94`: software metadata deliberately resides in provenance/detail. Full repeat JSON preserves version/model hash, provenance retains pinned scientific source/release identities (`backend/src/crispr_web/execution/provenance.py:85–98`), and native receipts bind the engine. The proposed omission is therefore **not an implementation defect**; reproduction requires the documented evidence package.

**Parameter checksum limitation.** Replacing `parameter_sha256` with 64 zeroes also passed both gates: backend checks hexadecimal shape, not an expected release-owned parameter digest (`validation_repeats.py:162–184`). Owned native tables and sealed runtime identity reduce the concern but do not turn shape validation into checksum authentication. A stronger binding requires an explicit trusted serialization/receipt policy; do not hardcode a fixture checksum or change scientific parameters as a shortcut.

## Action and acceptance criteria

**P2, implement after the complete council report:** independently validate positive probability entries against oriented sequence and the declared canonical/GU/minimum-loop model in Integration and backend. Cover isolated instance, consensus and local-context tables. Reject adjacent canonical pairs and distant noncanonical pairs, including the demonstrated GG case; accept valid GU/UG, both DNA orientations, legitimate crossing marginals and unchanged missingness. Do not import one validator into the other or rerun folding in validation. Propagate any release identity changes through the normal release workflow.

Parameter-digest binding is a separate release-design follow-up. Reference expansion, new biological classifiers, altered folding presets and automatic comparative-family construction require evaluation; none is justified as an immediate fix.
