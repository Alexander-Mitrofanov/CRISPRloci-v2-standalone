# Council 06 — CRISPRspacer

Reviewed 2026-10-14. Three members independently examined scientific intent, references/output/handoffs, and platform validation, then challenged one another's conclusions. Scope includes `protospacer`, `viral_search`, and the CRISPRspacer search reused by prophage context. The pinned tool is 0.3.1, commit `15298183a59b3027957a247d00323df759477f4e` (`tools/tools.lock.json:78–85`). No scientific sources, runtime, reference installations, or production services were changed.

## Four verdicts

1. **Author-intended integration: scientifically faithful, with a demonstrated exact-mode independent-validation gap.** Exact target-to-spacer search and heuristic spacer-to-viral search are correctly distinguished. Native tests pass. The web publication boundary nevertheless accepts invented reference labels/spacer identities in otherwise consistent exact-mode output; this is not evidence that native matching is incorrect.
2. **Required/background data: explicit operator provisioning is correct; current full production coverage is unknown.** Two distinct immutable reference bundles are needed. Local examples and release gates are small fixtures. Larger public collections merit evaluated subsets, not automatic replacement.
3. **Compact scientific output: substantially ready.** JSON preserves typed identities, coordinates, policy and missingness; previews are bounded. Public TSV escaping changes typed strand tokens, and the viral overview duplicates its detailed view.
4. **Downstream readiness: good evidence contracts and one real internal handoff; partial interactive reuse.** Source-spacer evidence already feeds prophage context. Search JSON is consumable evidence, but current sequence handoffs replay submitted input rather than exporting derived matched sequences. No existing downstream scientific module is shown to require a missing port.

## Scientific integration and boundaries

`protospacer` invokes `database-search` directly, without array detection (`Integration/crispr_integration/protospacer.py:162–199`). Its policy is full-length exact matching, both strands, linear targets, zero substitutions/gaps, unknown array overlap and unevaluated PAM (`:14–17`). The native index nominates 16-base prefixes and verifies the entire oriented spacer before emitting a hit (`tools/CRISPRspacer/src/crisprspacer/database.py:277–311`). A palindrome has one `both` orientation; repeated reference occurrences retain their identities. Coordinates are one-based inclusive in the submitted forward target frame. Unsupported circular-origin matches and substitutions are explicit scope limits, not integration failures.

`viral_search` reverses the direction: supplied spacer queries search an operator-pinned viral reference. Integration passes literal 0–2 allowed substitutions to `blastn-short` and replays the native bundle (`Integration/crispr_integration/viral.py:50–105`). Eligible queries are 18–80 unambiguous DNA bases. Acceptance requires a single full-query ungapped HSP; partial alignments, ambiguous subject bases and excessive substitutions are rejected. The orientation derives from both query and subject coordinate directions, with forward and query-frame subject sequences retained (`tools/CRISPRspacer/src/crisprspacer/viral_search.py:190–230`). Backend independently reconstructs these alignments against the pinned SQLite subject catalogue and recomputes counts/candidate summaries (`backend/src/crispr_web/execution/validation_viral.py:122–219,240–454`).

The [NCBI BLAST options](https://www.ncbi.nlm.nih.gov/books/NBK279684/table/appendices.T.blastn_application_options/?report=objectonly) support the chosen short-query profile. [NCBI search-parameter documentation](https://blast.ncbi.nlm.nih.gov/doc/blast-topics/blastsearchparams.html) describes the underlying search parameters. Successful execution does not make retrieval exhaustive: terminal mismatches can be clipped and therefore fail the full-query filter. Increasing the reference cannot remove that limitation. Missing taxonomy, confidence, host assignment and PAM compatibility remain missing; an E-value is not a targeting probability (`tools/CRISPRspacer/docs/contracts.md:29–48`).

The reused `self` stage extracts source-bound spacer occurrences from canonical detector reports, uses exact same-record search, and joins non-array hits to Phigaro regions (`Integration/crispr_integration/prophage_context.py:49–81`). Integration independently enumerates expected exact locations, including excluded source/other-array hits, before accepting context evidence (`Integration/crispr_integration/source_spacer_evidence.py:165–299`). This is an actual derived-evidence connection, without inferring infection or biological orientation.

## Demonstrated exact-mode validation gap

The chair's fixture mutation probe and the scientific member's separate real-native probe agreed. The latter built an actual SQLite index from the bundled three-record NCBI sample and ran the current native CLI through Integration. Baseline output contained one match and passed native replay and both platform gates. Three independent mutations were then made, with consistent retained files, TSV, counts where needed, and recomputed manifests:

- Replace the reported spacer ID with an ID absent from the catalogue.
- Replace reference name/release while keeping the pinned digest claim.
- Remove the sole match and update counts/outcome/stage to a coherent no-match result.

Integration and backend accepted all three; native `validate-database-result` rejected all three. The platform validators check source reconstruction and a claimed digest but receive no catalogue for membership/metadata verification (`Integration/crispr_integration/protospacer.py:75–158`; `backend/src/crispr_web/execution/validation_protospacer.py:46–166`; dispatch at `validation_pipeline.py:86–90`).

The scientific member challenged whether this implied broken native reference pinning. It does not: native `open_database` hashes SQLite and compares its internally bound metadata with `reference.json` (`database.py:210–245`). The data reviewer agreed the defect is defense in depth. A second challenge concerned the cost of independently proving completeness. Council resolution: **bounded reference/row binding is a safe immediate correction; exhaustive completeness is a separate design problem.** Checking at most the reported 10,000 rows cannot prove that no row was omitted. Do not disguise membership verification as exhaustive replay or add an unbounded second search.

## References and beneficial expansion

Exact mode needs a spacer catalogue; viral mode needs viral nucleotide sequences plus matching BLAST files. Configuration requires paired operator paths/digests and rejects symlinked reference roots (`backend/src/crispr_web/config.py:462–481`). The review shell has neither pair configured; release environment construction inherits operator settings (`scripts/manage_release.py:318–338`). This establishes neither presence nor absence of deployed references.

The documented 2017 research spacerome has 720,391 occurrence records, while the retained historical viral RefSeq 237 receipt describes 19,625 records and 583,708,944 bases (`tools/CRISPRspacer/docs/ncbi-spacerome.md:53–65`; `docs/viral-reference-methods.md:31–45`). These are previous import documentation, not fresh full-corpus verification. The [original spacerome article](https://pmc.ncbi.nlm.nih.gov/articles/PMC5605939/) identifies its research context. Release gates explicitly build three-record and synthetic viral references (`scripts/gate_release.py:59–96`), so passing them demonstrates mechanics rather than biological coverage.

[JGI SpacerDB](https://spacers.jgi.doe.gov/database/overview/) offers much broader metagenomic coverage: its documentation describes over 1.6 billion spacer occurrences and over 790 million high-quality spacers. Its [download guidance](https://spacers.jgi.doe.gov/quick_start/) provides nonredundant high-quality FASTA and selected subsets. This is not a drop-in replacement: the current importer caps source bytes at 512 MiB, decoded FASTA at 2 GiB and records at five million (`database.py:51–106`). A pilot should select an ecosystem/quality-defined subset, preserve release and source checksums, cluster-to-occurrence relationships and filtering counts, and measure added matches, redundancy and resource use. Predicted taxonomy must not become verified host assignment. [CRISPRCasdb downloads](https://crisprcas.i2bc.paris-saclay.fr/Home/Download) provide another genome-derived option; this review did not establish that its relevant collection is larger or better.

For viral coverage, [NCBI Virus documentation](https://www.ncbi.nlm.nih.gov/labs/virus/vssi/docs/help/) distinguishes RefSeq from broader GenBank nucleotide data, including incomplete and segmented records. A scoped GenBank extension may add useful sequence diversity but also redundancy and partial genomes. Preserve accession.version, collection scope, immutable source receipts and heuristic status; measure runtime, accepted/rejected HSPs and resource-limit failures against held-out controls. Broader data changes BLAST search space and E-values. No automatic catalogue update or relaxed resource limits is recommended. Non-NCBI collections would additionally require reference-aware links: `ViralResults.vue:28` currently constructs NCBI nuccore URLs for every accession.

## Output and handoffs

Compact exporters normalize repeated spacer/subject identities and retain policy, coordinates and heuristic completeness (`backend/src/crispr_web/publication/compact/search.py:6–95`). Exact previews cap rows and bytes; viral previews cap each inventory at 100 rows, with truncation flags (`summaries/protospacer.py:15–27`; `summaries/viral.py:30–44`). Full JSON exports remain independent of preview truncation. The explanatory text distinguishes missing evidence from zero matches, occurrence support from independent sequences, and sequence association from infection. These qualifications are scientific content.

Fresh exporter probes demonstrated that public TSV `relative_strand` becomes `'+` or `'-` because all formula-leading strings are escaped (`publication/protospacer.py:24`; `publication/viral.py:40–46`). JSON is unaffected. Both specialists challenged calling this biological corruption: native documentation explicitly describes spreadsheet escaping. Resolution: improve public TSV interoperability with a column-aware exception for validated strand enums, retaining protection for arbitrary IDs/titles; leave native replay formats unchanged. A smaller presentation improvement is to give the viral overview a compact form: `frontend/src/components/results/ResultsView.vue:369–381` renders the same full component on overview and detail tabs.

`input-sequences.json` republishes normalized original inputs (`publication/sequence_ports.py:38–105`), and port types remain target for protospacer and spacer for viral search (`frontend/src/contracts/module-ports-v1.json:10–15`). Neither this packet nor compact `result.json` is a derived match handoff. An optional matched-reference-spacer export could feed viral search, but must preserve catalogue/occurrence provenance and explicitly handle the exact-mode 16–1,000 versus viral 18–80 length policies. No result implies homologous array grouping, evolutionary orientation, a complete viral genome or a host assignment.

## Priorities, acceptance, and verification

**P1 engineering:** independently bind exact-mode report reference metadata and reported spacer IDs/sequences/eligibility to the operator-pinned catalogue. Preserve independent backend code, bounded metadata/row reads, immutable read-only access, SQLite cancellation and worker checkpoints. Acceptance: real-native baseline succeeds; invented ID, substituted catalogue sequence, false reference label and changed reference bytes fail at both boundaries. Do not scan the entire reference unboundedly.

**P2 engineering:** preserve validated public TSV strand enums while formula-like IDs/titles stay escaped; test `+`, `-`, `both`, missingness and numeric values. Optionally compact the viral overview while retaining complete detail/downloads and uncertainty language.

**P2 design/evaluation:** document the residual omitted-hit boundary; evaluate bounded independent indexed completeness verification under explicit shared work/candidate/time budgets before implementation. Evaluate reference expansion separately; no biological/model/data update is justified solely by size.

Real synthetic viral tests exercised Integration, backend replay and export. The separate real-native exact mutation probe closes the fixture-only limitation for the demonstrated gap. These are computational/contract checks, not newly measured biological sensitivity. No browser E2E, full-corpus performance test or production inspection was performed by this council.
