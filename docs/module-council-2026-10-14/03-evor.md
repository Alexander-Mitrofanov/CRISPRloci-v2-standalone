# Council 03 — CRISPR-evOr

Date: 2026-10-14. Scope: acquisition-order inference, scientific source, Integration, independent backend validation, public output and downstream handoffs. The pinned distribution is evOr **1.0.3**, commit `5120465837e37acb0dc39baae7a71c5ad94d3843` (`tools/tools.lock.json:48`). The chair and two specialists independently inspected the implementation, exchanged challenges, and resolved the findings below. Both specialists completed before final synthesis. Council 02 was consulted for shared boundaries; evOr impacts were independently verified. No implementation, runtime, reference dataset or production service was changed.

## 1. Author-intended integration — qualified pass

The central analysis matches the intended method. Integration invokes the dedicated command with CCDB groups, spacer clustering, saved reconstructed events, suppressed plots and bounded worker execution (`Integration/crispr_integration/runner.py:1021`, `:1222`). evOr forces comparison of input and reversed acquisition order. It deep-copies the groups, reverses the order and alignment columns for the alternative hypothesis, and estimates each tree separately when no independent tree is supplied (`tools/evOr/sp_model/run_experiments.py:162`, `:226`, `:244`). Integration does not reuse an input-order SpacerPlacer tree or run a competing standalone reconstruction; evOr supplies the selected reconstruction (`runner.py:1183`). The conflicting `sp_model` packages remain isolated.

The selected protocol copies the whole winning fit, including counts, rates and correction provenance. Reverse selects reverse; Forward and ND retain input order (`tools/evOr/sp_model/orientation/orientation_tools.py:96`). The signed difference remains input minus reverse even when the selected CSV's primary likelihood belongs to reverse. Decisions are strict: equality at either threshold is ND (`orientation_tools.py:132`). Both independent validation layers recompute that decision, compare CSV/JSON likelihoods, enforce exact leaf membership and check the selected tree against its branch sum (`runner.py:526`, `:967`; `backend/src/crispr_web/execution/validation_orientation.py:99`, `:153`).

The [primary study](https://journals.plos.org/ploscompbiol/article?id=10.1371/journal.pcbi.1013706) supports independent trees when available and separate estimation otherwise. Its empirical threshold is an evidence rule, not a calibrated probability. Acquisition direction must not be promoted to transcription, leader or PAM orientation. Current presentation explicitly retains these distinctions (`frontend/src/components/results/orientation/OrientationResults.vue:181`; `history/AncestralHistoryExplorer.vue:378`).

Two demonstrated boundary defects qualify the pass. First, unlike standalone reconstruction, evOr's gates omit deletion-rate and deletion-count validation, despite publishing those fields. Second, Integration validates correction metadata but does not bind selected-CSV statuses to the selected hypothesis; backend validation ignores correction policy and per-direction statuses entirely (`runner.py:581`, `:609`, `:865`; `validation_orientation.py:35`). These are independent validation gaps, not evidence that native inference chose the wrong hypothesis.

## 2. Required data and larger datasets — no missing background database

evOr reconstructs the submitted cohort rather than querying a biological reference database. The required symbolic/callable likelihood resources are included by package-data (`tools/evOr/pyproject.toml:46`). Real native runs below exercised the existing isolated environment and MAFFT; no model or database download was needed.

The authors anticipate improved coverage from additional closely related arrays. Their evaluation used biologically restricted cohorts and core-gene phylogenies. The platform's exact canonical-repeat identity and transitive exact spacer-overlap grouping are conservative input rules, not equivalent to those research-cohort filters (`Integration/crispr_integration/adapter.py:83`, `:106`). The council rejected calling that difference a demonstrated integration defect: genus/Cas annotations and independently justified relationships cannot simply be invented.

A curated augmentation feature could help users lacking informative related arrays, but requires provenance, compatible repeat/array families, genuine spacer overlap, diversity, duplicate control, assembly-quality checks and measured orientation stability. Unrelated or redundant arrays can increase cost without information. Larger inferred trees also make computation and interpretation harder; native guidance warns that tree quality and observable events affect rates (`tools/evOr/README_SPACERPLACER.md:548`, `:568`, `:580`). Public independent-tree uploads and broader homology grouping are separate scientific/input-contract projects. No automatic reference expansion is recommended by this audit.

## 3. Compact scientific output — good structure; integrity and wording fixes

Compact `result.json` contains group/member identities, both likelihoods and trees, threshold, selected metrics and correction provenance. ND explicitly uses `selection_basis: "unresolved_default"`; it does not claim input-order support (`backend/src/crispr_web/publication/compact/evolution.py:137`). The browser starts with an evidence plot and expandable likelihood/tree detail. Both histories are discoverable, canonicalized to shared spacer identities and bounded, with omissions reported (`summaries/reconstruction_discovery.py:94`, `:156`, `:184`). Native event files remain available through bounded publication; the interface distinguishes model-estimated ancestry from observed leaves. More prose or additional plots are not the priority.

**Shared numeric-boundary defect, independently demonstrated here.** A fresh synthetic Worker run published `deletion_rate_bdm=-7`, `reconstructed_deletions=-5`, and `alpha_bdm="NaN"`. Integration independently accepted the same files. evOr's omission includes core selected reconstruction fields that standalone already checks, extending Council 02's optional-metric finding (`validation_orientation.py:115`; `publication/compact/evolution.py:11`). Generic CSV coercion retains nonfinite tokens as strings (`summaries/result_tables.py:28`). Typed public numbers need metric-specific validation and explicit supported missingness.

**Shared correction-boundary defect, with an additional evOr linkage gap.** The same run published selected CSV alpha/rho statuses `disabled` while both hypothesis records said `applied`. Both gates accepted this contradiction. Separately, the backend accepted an invented forward alpha status and a mismatched requested-correction flag. A correction check must use the admitted **effective** setting after operator override (`backend/src/crispr_web/service.py:178`, `:242`). Selected CSV statuses must match reverse metadata only for Reverse and forward metadata for Forward/ND. A valid alternate-hypothesis fallback must remain separately attributable. Preserve native `not_applicable` cases and explicit warning provenance.

**New proven wording defect.** Native metadata says rho fallback changes the IDM/BDM likelihood-ratio test (`tools/evOr/crispr_evor.py:267`); its warning/docs and the advanced-options help repeat that implication (`sp_model/run_reconstruction.py:63`; `README.md:89`; `Integration/README.md:120`; `frontend/src/components/submission/AdvancedOptions.vue:177`). Pinned code changes optimizer parameter values, not their objective values (`sp_model/reconstruction_tree.py:1003`); log likelihoods and LRT use the unchanged objectives (`run_reconstruction.py:506`). Paired native runs confirmed this. Correct the prose to describe affected rate estimates and unchanged likelihood-based comparison; do not change the scientific formula to fit the prose.

Two minor native CLI help statements also lag behavior: threshold help excludes equality from ND, and event export help claims plotting is required (`tools/evOr/spacerplacer.py:241`, `:252`). Current tests and no-plot native exports contradict those statements.

## 4. Downstream readiness — observed ports ready; inferred histories are evidence

Orientation jobs emit source-verified observed `arrays.json`, `repeats.json` and `spacers.json`, preserving coordinates, hashes, occurrence identities and explicit incomplete states (`backend/src/crispr_web/publication/sequence_ports.py:115`; `array_data.py:174`, `:225`). Compatible CCTK, repeat-analysis, spacer-search and association workflows can consume those ports. They correctly preserve source-forward DNA; evOr's acquisition-order decision cannot establish transcription strand or authorize reverse-complementing downstream search input.

`input-sequences.json` replays original input. `result.json` is compact evidence, not an accepted submission port. Both hypotheses and native ancestral events support external inspection, but no existing curated consumer requires an inferred-ancestor port. A future consumer needs versioned group/leaf/spacer identities, both hypotheses, selection basis and uncertainty, without fabricating ancestral DNA or homology. The defects above affect trust in exported metrics/provenance, not the verified observed-sequence ports.

## Council challenge and resolution

The output specialist challenged a blanket “all numerics must be finite” fix. The author specialist independently confirmed deliberate missing alternative estimators (`tools/evOr/sp_model/run_reconstruction.py:524`) and warned against arbitrary alpha ceilings. The chair accepted metric-specific rules: reject impossible counts/rates and malformed present evidence; retain supported missing estimates, legitimate negative log likelihoods and finite extreme alpha. No universal nonnegative-LRT rule is justified.

The author specialist challenged calling histories “pipeline-ready”: they are auditable evidence, whereas existing submission ports carry observed data. All members adopted that distinction. The chair challenged whether correction statuses should follow user request, and both specialists resolved the expectation to the effective admitted setting and the actually selected orientation. ND remains an unresolved reporting default. Finally, the rho/LRT wording claim was challenged against code and paired native measurements rather than accepted from documentation; the evidence supports a wording fix only.
