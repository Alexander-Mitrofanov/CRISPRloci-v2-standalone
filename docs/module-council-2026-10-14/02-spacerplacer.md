# Council 02 — SpacerPlacer

Date: 2026-10-14. Scope: the standalone reconstruction workflow, its scientific source, adapter, independent backend gate, public evidence and downstream ports. The reviewed source is SpacerPlacer `1.0.1.post3`, lock commit `0e4c22494829f8c3a3a7bf6b78203314651826c9` (`tools/tools.lock.json:38`). Three members independently reviewed scientific intent, references/output, and platform boundaries, then exchanged challenges and rebuttals. Both specialists completed before synthesis. This is a report; no source, models, runtimes or production services were changed.

## 1. Author-intended integration — qualified pass

The main invocation and order contract are sound. Integration creates groups containing at least two arrays, calls native CCDB input with spacer clustering, saves reconstructed events, suppresses plot generation and console verbosity, and preserves worker isolation (`Integration/crispr_integration/adapter.py:164`; `Integration/crispr_integration/runner.py:1021`). Source-frame arrays with unknown strand are explicitly excluded. Source-negative arrays go into `neg_strand`; already biologically oriented arrays go into `pos_strand`, preventing double reversal (`adapter.py:200`, `adapter.py:233`). Native parsing reverses negative arrays’ spacer order and reverse-complements their sequences exactly once (`tools/SpacerPlacer/sp_model/input_parser.py:93`). A fresh native round-trip probe confirmed this behavior.

Standalone reconstruction preserves the supplied order. When evOr is requested, Integration uses evOr’s selected reconstruction rather than running a competing input-order analysis (`runner.py:1183`). Core Integration and backend checks require exact group membership, unique expected tree leaves, finite core estimates, nonnegative counts and agreement between reported and actual tree length (`runner.py:720`; `backend/src/crispr_web/execution/validation_reconstruction.py:18`). No scientific code import combines SpacerPlacer with evOr’s conflicting `sp_model` package.

Grouping is deliberately conservative: exact reverse-complement-canonical repeat identity, followed by transitive exact spacer overlap, precedes native approximate spacer clustering (`adapter.py:83`, `adapter.py:106`). Thus increasing spacer distance cannot reconnect groups already excluded for having no exact overlap. This is a scope limitation, not proof that current groups are wrong. The authors’ published cohort used additional biological subdivision and diversity filtering; their software supports two-array inputs. Differences between a research cohort and a supported input interface do not justify silently changing grouping. [Author repository](https://github.com/fbaumdicker/SpacerPlacer), [primary study](https://pmc.ncbi.nlm.nih.gov/articles/PMC11472070/).

Two engineering gaps qualify the pass. First, backend validation does not independently verify native alpha/rho correction status or its agreement with effective job settings. Integration does (`runner.py:775`), but the backend gate neither requires those columns nor receives the effective correction flag (`validation_reconstruction.py:27`; `validation_pipeline.py:157`). Second, additional scientific fields exported publicly have weaker validation than core fields; the publication map accepts them through generic CSV coercion (`backend/src/crispr_web/publication/compact/evolution.py:11`, `:61`; `summaries/result_tables.py:28`). Fresh mutation probes below demonstrate both gaps.

## 2. Background data and larger datasets — no missing biological database

SpacerPlacer reconstructs the submitted comparative observations; it does not need a search database of reference genomes, phages or CRISPR arrays. Both active symbolic likelihood resources are present, and package-data includes their directory (`tools/SpacerPlacer/pyproject.toml:46`). No database download is justified by this audit.

More complete, appropriately related arrays can increase information, but redundant sampling and mixed biological groups can worsen interpretation. Selection by detection category, resolved orientation and overlap also defines an ascertainment boundary: the analysis does not represent every CRISPR array in an organism or population. Additional cohorts should preserve source identity, biological comparability, orientation and spacer order, and be evaluated for diversity and sensitivity to sampling. Automatically merging external arrays would change the question being answered.

The authors warn that tree quality, timescale and sparse events strongly affect reconstruction and rate estimates, particularly individual-group estimates (`tools/SpacerPlacer/README_UPSTREAM.md:611`). Independent, justified phylogenies can be beneficial; indiscriminate larger datasets are not a substitute. The present pipeline supplies no external tree, so native inference constructs one from arrays (`runner.py:1195`; `tools/SpacerPlacer/spacerplacer.py:80`). Its rates must not inherit the mutation-rate or time interpretation of the paper’s calibrated analyses. [Author guidance](https://github.com/fbaumdicker/SpacerPlacer), [primary study](https://pmc.ncbi.nlm.nih.gov/articles/PMC11472070/).

Adding uploaded trees, broader homology grouping or population reference cohorts would require a separate scientific design, provenance contract, bounded validation and evaluation. These are not routine missing-data repairs.

## 3. Compact scientific output — useful, with correctness fixes required

The compact result selects groups, identities, excluded arrays, tree strings and scientific estimates; it avoids copying logs and large native structures into the main evidence object (`publication/compact/evolution.py:78`). Exact estimates are collapsed in the UI, and existing model detail already explains dependence on tree branch scale (`frontend/src/components/results/reconstruction/DeletionModelEvidence.vue:106`). This is an appropriate basic presentation.

Standalone presentation nevertheless borrows orientation-comparison semantics. With no comparison, `ReconstructionStory.vue:25` assigns “Unresolved,” while `ReconstructionResults.vue:77` describes decisive/unresolved hypotheses and reports tree policy as “not reported.” Independent Vue rendering confirmed the latter text. An order that was never compared must be described as supplied input orientation, not as an inconclusive test. The standalone evidence should also identify the inferred tree and uncalibrated scale. This corrects interpretation without changing any inference.

Optional published values need typed handling. In a synthetic CSV, `alpha_bdm="NaN"` and `nb of reconstructed duplications=-5` passed both validation layers; a complete synthetic Worker execution then published the string and negative count in `result.json`. A separate full Worker mutation published alpha/rho statuses `disabled` although effective corrections were enabled; Integration would have rejected that case. The latter demonstrates a missing independent defense, not failure of the normal Integration gate.

A blanket finite-value rule across all native CSV columns would be scientifically wrong. Alternative estimators deliberately use `np.nan` when unavailable (`tools/SpacerPlacer/sp_model/run_reconstruction.py:527`). The main alpha optimizer is bounded at one, but subsequent correction has a zero-event edge (`reconstruction_tree.py:1028`, `:1127`). A fresh native zero-loss reconstruction produced alpha `9007199254740992`, zero rates and a recorded rho fallback; native code explicitly warns that parameter estimates and model testing are not meaningful without losses (`run_reconstruction.py:512`). Preserve finite extremes rather than inventing caps. Undefined optional estimates require missingness and a reason, not zero or a string masquerading as numeric evidence. Finite likelihoods and likelihood-ratio differences may legitimately be negative.

The native event files are retained in the bounded results ZIP. Standalone summary construction currently exposes only results and trees, whereas the interactive history explorer reads orientation histories (`summaries/result_tables.py:182`; `frontend/src/components/results/history/AncestralHistoryExplorer.vue:28`). This is a useful future presentation enhancement, not destroyed evidence. Publication limits can omit files with warnings; no unqualified “complete ZIP” promise is appropriate (`publication/discovery.py:58`).

## 4. Downstream readiness — observed ports ready; histories remain evidence

Reconstruction jobs expose `arrays.json`, `repeats.json` and `spacers.json` through the same source-verification boundary as detection. Repeat/spacer records require exact source intervals and sequences, retain source hashes and occurrence identity, and mark incomplete ports explicitly (`backend/src/crispr_web/publication/array_data.py:27`, `:225`; `sequence_ports.py:115`). These are observed data, including observations that reconstruction may exclude. Compatible repeat analysis, spacer search and array-comparison workflows can reuse them without treating inferred ancestors as observed DNA.

`input-sequences.json` replays original input. `result.json` is a compact evidence document, not an accepted sequence submission port. No existing pipeline consumer was found that requires synthesized ancestral DNA. Trees, rates and native event files support external analysis, but reconstruction numbers and inferred states must retain their identity maps and model-estimated status. A future structured standalone-history export should validate tree/node/spacer consistency and clearly distinguish inferred states from observed sequences.

## Council challenge, rebuttal and resolution

The scientific reviewer challenged the interpretation that stricter grouping differs from authors’ intent: both other members accepted that cohort-specific biological filters cannot be added without evidence. The output reviewer challenged a possible “missing events” finding: ZIP discovery includes those files, so the finding became presentation/discoverability only.

The chair’s correction-policy finding survived challenge, with one crucial refinement: use the admitted **effective** correction setting, not the requested setting, because operator policy can disable corrections (`backend/src/crispr_web/service.py:178`). Summary sanitation checks stage metadata shape, not native-CSV agreement (`summaries/bias.py:39`). All members agreed that it does not replace independent validation.

Both specialists challenged uniform numeric rejection. Their native/source counterexamples established deliberate missing alternative estimates and extreme no-loss alpha behavior. The resolved recommendation targets allowlisted public fields and explicit missingness. No model formula change, arbitrary alpha ceiling or universal nonnegative-LRT rule is authorized by this evidence. A null-deletion UI probe also triggered a zero-loss warning through `Number(null) === 0`; this is lower-priority robustness, because current validated reconstruction outputs require a deletion count.

Priorities for the separate implementation agent:

1. **P1 — independent correction provenance:** validate CSV status/policy against effective settings; require exact fallback warning provenance, reject strict-policy fallback and metadata disagreement. Worker mutation regressions must fail before publication; legitimate applied, disabled and permitted fallback cases must pass.
2. **P1 — public numeric semantics:** independently reject negative/fractional event counts and malformed present numeric evidence; preserve optional missing/undefined estimates explicitly. Test negative likelihoods, finite extreme alpha, blank optional values and native deliberate missing estimators. Do not alter scientific formulas.
3. **P1 — standalone scientific wording:** distinguish “input orientation; not compared” from genuine evOr inconclusiveness; expose known tree source/scale. Cover standalone and Forward/Reverse/ND cases in component and browser tests; null counts must not imply zero.
4. **P2 — optional standalone histories:** only if undertaken, reuse bounded identity-checked event presentation and preserve ZIP access, truncation notices and inferred-state semantics.

Changes must preserve independent validators and environment isolation, propagate relevant contracts/release identities, and pass applicable `scripts/check.sh` checks, browser coverage and the private-data scanner. No engineering blocker prevents these fixes. Scientific expansion or altered zero-information fitting requires evaluation beyond this audit.
