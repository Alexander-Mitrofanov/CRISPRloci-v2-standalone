# Council 01 — CRISPRtracrRNA-v3

Reviewed 2026-10-14. Scope: pinned revision `9811f27d202582345bf54e5c34c911c269135992`, its platform integration, reference assets, public results and downstream contracts. The chair commissioned two independent specialists, exchanged their findings, requested challenges and rebuttals, and resolved the findings below before writing this report. This council made no implementation, runtime, reference or production changes.

## Four verdicts

| Question | Verdict |
| --- | --- |
| Author-intended integration | **Qualified pass.** Supported model and complete workflows are correctly selected; native dependencies and independent backend gates are present. Standalone Integration validation and several public-field checks require repair. |
| Missing or better background data | **No missing bundled runtime data found.** All 27 resource hashes match. Larger public catalogues are potential evaluation/training resources, not interchangeable runtime databases. Broader subtype coverage requires separately validated models. |
| Compact, scientific output | **Good structure, with confirmed information loss.** Computed IntaRNA energies disappear, and model-only semantic labels become null. Existing warnings correctly preserve uncertainty and should remain. |
| Downstream readiness | **Usable through complete exports and manual curation; incomplete for candidate-specific typed handoff.** Original target-DNA reuse works. Candidate-to-RNA-family transfer needs explicit homology selection and a provenance-aware contract. |

## Integration and scientific fidelity

The original authors combine covariance models with repeat, interaction, terminator and Cas-context evidence, and document separate model-only and complete modes. The platform follows that distinction: `tracrrna` invokes `--mode model`, while `loci` invokes `--mode complete`, passing configured upstream executables and supported scientific settings through argument arrays (`Integration/crispr_integration/annotations.py:215`). This matches the maintained V3 branch (`tools/CRISPRtracrRNA-v3/src/crisprtracrrna/pipeline.py:141`). [Original author repository](https://github.com/BackofenLab/CRISPRtracrRNA), [original paper](https://academic.oup.com/bioinformatics/article/38/Supplement_2/ii42/6702007).

V3 intentionally fixes historical coordinate, evidence-selection and ranking behavior; exact numerical identity to the historical implementation is not its contract (`tools/CRISPRtracrRNA-v3/docs/MIGRATION.md:38`). Its native README explicitly describes candidate intervals as search windows or model-supported regions, not confirmed full transcripts (`README.md:140`). The platform correctly distinguishes ranking scores from covariance-model bit scores and labels neither as probabilities (`frontend/src/components/results/annotations/AnnotationResults.vue:247`).

The backend independently binds records to submitted sequence and file hashes, reconstructs reverse-strand candidates, checks policy and coordinates, and validates nested reports in complete mode (`backend/src/crispr_web/execution/validation_annotations.py:205`). IntaRNA is present through a separate native environment added to the launcher path; its absence from the main tracrRNA Conda package list is deliberate (`scripts/provision_tools.py:362`). Nested upstream pins agree with the parent lock. These findings support correct software integration; they do not establish biological sensitivity or specificity.

## Confirmed defects

**C01-1, P2: computed interaction energy is silently discarded.** Native parsing emits `interaction.energy_kcal_mol` (`tools/CRISPRtracrRNA-v3/src/crisprtracrrna/search.py:379`), and the native CSV exporter uses that same field (`reporting.py:109`). The backend reads `interaction.get("energy")` instead (`backend/src/crispr_web/summaries/annotations.py:95`). A temporary synthetic complete-mode report with native-shaped Cas metadata and energy `-7.5` passed the summary/export path without warnings; summary and compact result contained null, and TSV contained a blank. This reproduces serialization loss, not a newly executed native prediction.

**C01-2, P2: model-only interpretation fields are lost.** `merge_model_hits` omits `candidate_origin`, `evidence_class` and `boundary_kind` from prediction JSON (`tools/CRISPRtracrRNA-v3/src/crisprtracrrna/evidence.py:188`). Its native CSV exporter supplies the established labels `covariance_model`, `cm_only` and `merged_model_region` (`reporting.py:95`). The backend uses bare `.get()` calls (`backend/src/crispr_web/summaries/annotations.py:82`), leaving all three null and producing “Not reported” in the browser. A temporary model fixture reproduced this without warnings. These labels describe known algorithmic output; restoring them does not invent biological evidence.

**C01-3, P2: standalone Integration does not reconstruct candidate bases.** Its gate checks length and strand but not sequence equality to the submitted interval (`Integration/crispr_integration/annotations.py:146`). The chair supplied source `ACGTACGT`, interval `2..4`, strand `-`, and candidate `CGT`; the correct oriented sequence is `ACG`. After retaining the consistently hashed record, `validate_tracr` accepted it and returned one prediction. The backend already rejects this mutation (`backend/src/crispr_web/execution/validation_annotations.py:270`), so this is an independent adapter-contract gap, not evidence of a public API bypass. The same Integration function also lacks the backend's declared-coordinate, strict identity/uniqueness and disabled-experimental-policy checks.

**C01-4, P2: impossible public anti-repeat fractions escape independent validation.** A temporary backend fixture carrying `anti_repeat.identity=2.0` and `coverage=-1.0`, with consistent retained hashes, returned `completed` and published both values. Native parsing defines identity and coverage as fractions (`tools/CRISPRtracrRNA-v3/src/crisprtracrrna/search.py:126`); the backend checks other metrics but omits these copied fields (`validation_annotations.py:275`; `summaries/annotations.py:93`). This proves a malformed-output gate weakness, not that honest native execution produces these numbers. The repair should validate the fields actually published, including native interaction energy, without attempting to rerun the scientific scoring algorithm.

## Background data and improvement opportunities

All **27/27** files enumerated in `tools/CRISPRtracrRNA-v3/src/crisprtracrrna/data/manifest.json` were present and matched SHA-256. The assets include the Type II CM, four Type V-K CMs and indexes, and the terminator resources. Their retained provenance is documented at `tools/CRISPRtracrRNA-v3/THIRD_PARTY.md:9`; selection is explicit in `src/crisprtracrrna/config.py:154`. This workflow does not depend on an unprovisioned large sequence-search database.

The tool's existing literature inventory already records 304,447 entries and 42,712 unique normalized sequences, including 303,646 computational predictions (`tools/CRISPRtracrRNA-v3/docs/LITERATURE_BENCHMARK.md:3`). Fresh inspection of the author Atlas repository still found v1.0, already inventoried. Rfam RF02348 currently lists 37 seed and 41 full-alignment sequences; the 37-sequence seed is already covered by the local inventory. These observations do not identify a substantial missing runtime resource. [Atlas repository](https://github.com/Profluent-AI/CRISPR-Cas-Atlas), [Atlas paper and availability](https://www.nature.com/articles/s41586-025-09298-z), [Rfam RF02348](https://rfam.org/family/RF02348).

A useful scientific follow-up is an independent, subtype-stratified evaluation using native transcripts and annotated negative regions, separating training overlap and related clades. Predictions, engineered guide components and native transcripts must retain distinct evidence labels. Adding many predictions cannot by itself calibrate false discovery or establish functional tracrRNAs. Type V must remain explicitly scoped to **V-K**; additional Cas12 subtypes need curated evidence and evaluated models. [Author Type V-K study](https://academic.oup.com/microlife/article/doi/10.1093/femsml/uqaf020/8239287).

## Output and downstream exchange

The compact result contains source identity, digest, coordinates, strand, oriented sequence, score semantics and sparse evidence (`backend/src/crispr_web/publication/compact/annotations.py:30`). Full exports are rebuilt independently of browser preview limits (`backend/src/crispr_web/publication/annotations.py:19`). Eight default candidate columns and concise uncertainty statements provide a reasonable scientific display; removing the candidate/boundary/zero-result caveats would make it less accurate. Additional evidence is better suited to expandable candidate details than extra default columns.

Candidate FASTA and TSV support manual curation. Automatic sequence ports currently export the original target DNA (`backend/src/crispr_web/publication/sequence_ports.py:102`). That supports genomic reuse but is not candidate RNA export. The existing `SequenceOrigin` requires array identifiers and ordinals, lacks candidate strand/boundary semantics, and the sequence ID regex excludes the native dotted candidate IDs (`backend/src/crispr_web/exchange.py:52`). A direct cast into that contract would lose provenance or fail validation.

A future candidate handoff should require explicit family selection, preserve a candidate/source crosswalk and oriented coordinates, and pass ordinary RNA-family admission limits. Arbitrary candidates from one run are not established homologues; their windows are not established mature transcript boundaries. Existing manual export remains the defensible route until a versioned contract and curator-facing selection flow are implemented.

## Council debate and resolutions

The author reviewer initially judged the supported workflow faithful. The chair challenged whether that verdict survived an accepted false reverse-strand sequence. Both specialists agreed to narrow the verdict: command orchestration is faithful, but Integration's own output gate is incomplete. Independent backend rejection limits the consequence without fulfilling the adapter's separate responsibility. This distinction prevents both an unjustified production-bypass claim and dismissal of a real contract defect.

The output reviewer proposed recovering model-mode labels. The author reviewer challenged whether that would fabricate missing evidence. Inspection of native CSV defaults and the exact model branch resolved the disagreement: derive the three known labels only for absent keys in validated model mode. Preserve explicit values/nulls and unknown complete-mode evidence. The energy loss was independently reproduced by both specialists and accepted as a definite mapping error.

The council also challenged “larger dataset” as an assumed improvement. Asset verification and fresh primary-source checks found no omitted runtime resource; the large development catalogue already distinguishes predictions from native evidence. We rejected an automatic replacement or expansion recommendation. Likewise, the team rejected automatic forwarding of every candidate to RNAalifold. Homology and boundary selection remain scientific decisions. The unexposed optional Type V motif flag was classified as a possible feature extension, not a failure of the supported workflow.

## Implementation priorities and acceptance criteria

1. **Repair C01-1 and C01-2 first.** Map the native energy key, document kcal/mol units, preserve zero/negative/null values, and derive only absent model-mode labels. Test native-shaped model and complete fixtures through summary, full JSON/TSV and compact result; verify complete-mode boundary distinctions remain intact. Refresh affected public examples through the established generation path.
2. **Repair C01-3 and C01-4 independently at both gates.** Reconstruct source-oriented candidate sequence in Integration; check coordinate declarations, unique valid IDs and experimental-policy exclusion. Validate optional anti-repeat fractions as finite non-boolean numbers in `[0,1]` and energy as finite numeric evidence, preserving genuine nulls. Test both strands, ambiguity complements, wrong equal-length sequences, duplicate IDs, malformed coordinates/policy, fractions outside range and wrong types. Keep backend validation independent of Integration imports.
3. **Treat dataset expansion and candidate handoff as separately validated enhancements.** Define evaluation panels before model changes. Design candidate provenance and explicit homology selection before extending typed exchange. Do not enable experimental rescue, change models/thresholds, or download references during jobs as part of the repairs.

## Evidence and limitations

Fresh specialist checks passed **386 native-package portable tests**, with **7 native integrations deselected**, plus **44 focused Integration/backend annotation and scientific-option tests** with **5 deselected**. Temporary serialization and malformed-output probes are described above. The root's fresh `scripts/check.sh` baseline passed **1,414 Python tests**, **396 frontend tests**, lint/build/privacy checks; **70 opt-in native tests were skipped**. The sandboxed FastAPI bridge issue was resolved by the root's approved local test run, not by weakening tests.

No fresh installed-tool biological execution or independent sensitivity/specificity benchmark was performed. Historical benchmark claims and public examples are context, not fresh native proof. Root verification found every scientific checkout clean and matching its lock with privacy hooks configured; root Git metadata itself was inaccessible. The subsequent implementation phase must run the appropriate platform checks and preserve release/contract propagation requirements.
