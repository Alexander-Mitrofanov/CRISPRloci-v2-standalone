## Method and source interpretation

The [original ISEScan paper](https://academic.oup.com/bioinformatics/article/33/21/3340/3930124) describes gene prediction, transposase profile/singleton searches, boundary extension using repeated copies and inverted repeats, and final refinement. Its 621 reference clusters include 355 singleton queries rather than 621 multi-sequence HMMs. Current native code uses FragGeneScan with `seq_type='0'` and `illumina_5`, then the bundled HMM and singleton assets (`tools/ISEScan-v2/isescan_v2/native/isPredict.py:100–138`; `native/constants.py:25–31`).

The wrapper invokes native ISEScan without `--removeShortIS`; native defaults therefore retain complete and partial calls (`isescan_v2/__main__.py:53–63`; `native/isescan.py:35–47`). Integration supplies normalized DNA, caps native threads at eight, uses shell-free worker invocation, and validates the resulting JSON against source DNA and native TSV (`Integration/crispr_integration/insertion_context.py:25–29,32–76`). The backend independently reconstructs the report from original persisted inputs and native TSV, verifies hashes, options and counts, and imports neither Integration nor the scientific validator (`backend/src/crispr_web/execution/validation_insertion_context.py:24–72`).

Coordinates remain 1-based inclusive in the source-forward frame. ORF strand belongs to the transposase, not an independently inferred orientation of the whole IS. TIR validation checks left source sequence, reverse-complemented right sequence, coordinates, matching columns and gaps. Missing transposase evidence and its copy E-value remain null; best-copy evidence remains distinct. TSD is explicitly unassessed (`isescan_v2/report.py:143–222`). Native `c`/`p` classification depends on length, copy number, E-values and TIR evidence (`native/pred.py:1977–2066`), so “partial” must not be expanded into a claim of physical truncation or inactivity. Contig-edge status is separate.

Nearest Cas cassettes are a bounded coordinate join with explicit ties and truncation, not disruption analysis (`backend/src/crispr_web/summaries/context_annotations.py:8–38`). This council inspected that handoff only, without reopening the excluded Cas tool audit.

## Demonstrated engineering finding

**P2 — reject double-gap TIR columns independently at both platform gates.** The tool rejects any alignment column containing `-` on both sides (`isescan_v2/report.py:175–180`), with an existing regression at `tools/ISEScan-v2/tests/test_reports.py:100–103`. Integration's predicate at `insertion_evidence.py:160–165` and the independent backend predicate at `validation_insertion_evidence.py:175–180` omit this check.

A fresh mutation probe used source `AAAACCCCTTTT`, terminal intervals 1–4 and 9–12, alignment `AA-AA:AA-AA`, alignment length 5 and one gap column. Ungapped DNA and the reported metrics agree, but the alignment contains a structurally invalid double-gap column. The scientific normalizer rejected it. Integration `validate_report` accepted the reconstructed report, and the complete backend `validate_insertion_context_pipeline` returned `True` with otherwise valid fixture evidence. Thus this is demonstrated validation drift, not merely a missing test. No evidence shows that the current native engine emits this malformed alignment.

**Acceptance:** independently add the double-gap rejection to both gates; exercise coherent TSV-plus-JSON mutations through each complete validation entry point. Reject internal and terminal double-gap columns while retaining valid singly gapped alignments, source-forward/right-reverse-complement binding, absent-TIR sentinels, nullable ORFs and complete/partial calls. Keep validators independent; do not re-execute science during publication or introduce broader biological filters. Follow release identity requirements for changed Integration code.

## Fresh native evidence and limits

The scientific specialist copied the exact pinned source to a temporary directory, checked the reused SSW binary's accompanying C/header against bundled sources, and ran real FragGeneScan, HMMER, BLAST and SSW. This was not an adapter fixture. The existing compatibility environment used Python 3.12.7, NumPy 1.26.4, SciPy 1.17.1, Biopython 1.86, fastcluster 1.2.6, FragGeneScan 1.32, HMMER 3.4 and BLAST 2.12.0+. It differs from `environment.yml:7–14` and the runtime lock description, notably Python 3.11 and BLAST 2.16.0. An older installed Python package was not used as evidence for current source behavior.

The bundled 42,245-base `NC_012624.fna` produced one `IS5_222` partial prediction at 30,355–31,343, ORF 30,399–31,298 on `+`, with 20 identical positions in a 28-column TIR alignment, in about 18 seconds. A 1,000-base repetitive negative returned zero calls in about six seconds. The verified reverse complement of the positive input returned zero calls in about 20 seconds under the same settings and model bytes.

The latter result was traced before coordinate serialization: the expected reverse ORF counterpart is 10,948–11,847 on `-`, whereas FragGeneScan produced 10,911–11,847, with a different 311-residue peptide versus 299 residues forward. The forward IS5 hit had full-sequence/domain E-values of `1.4e-37`/`1.7e-37`; the corresponding reverse peptide's best reported hit was an IS4 singleton at `0.63`/`1.0`, without a reported IS5_222 hit. This establishes orientation sensitivity in this tested source/dependency combination, not its prevalence or a universal strand defect.

**Evaluated follow-up:** reproduce forward, reverse-complement and cropped/fragmented controls in the exact release environment, then compare the original author implementation and inspect gene predictions/translation and HMM selection. Establish agreed sensitivity, false-positive, boundary and resource criteria before changing caller settings, models or combining orientations. No exact-release or original-author comparison was run here. Automatically running both orientations and merging calls would change the method and is not an approved engineering fix. Existing no-call wording correctly avoids claiming biological absence (`frontend/src/components/results/InsertionContextResults.vue:19–24`).

## References, output and compatible reuse

Fresh inspection counted 266 HMM profiles (40,472,487 bytes) and 355 singleton proteins (100,094 bytes). Their SHA256 values match `UPSTREAM.json:6–8` and both platform validators' model pins. `NOTICE:4–6` documents the supplied upstream models and explicitly excludes an independent ISfinder database. The [official ISfinder terms](https://isfinder.biotoul.fr/about.php) require written authorization for database download and prohibit third-party distribution, including through web software. Upstream repository licensing does not establish permission for a new bulk ISfinder acquisition.

Any proposed reference expansion must specify source/release identity, permissions, immutable hashes, taxonomic/family scope, cluster labels, profile/singleton compatibility, thresholds or recalibration, held-out family/taxon and fragmented-input evaluation, and runtime/memory cost. The observed reverse-input sensitivity must not be attributed to incomplete model files: the files are complete, and the translated peptide changed.

`publication/compact/insertion_context.py:4–9` retains the complete public report. It includes source/element hashes, family/cluster, native classifications, copy count, distinct E-values, nullable ORFs, full TIR alignments, explicit unassessed TSD and coordinate-only Cas relations. `summaries/insertion_context.py:29–36` alone limits the preview. This matches the insertion contract in `docs/module-results.md:61`; no evidence supports redesigning compact output merely because it retains substantial scientific detail. Bounded publication reports unavailable export explicitly rather than substituting empty findings (`publication/module_result.py:66–98`).

The insertion TSV already emits validated `+`/`-` outside arbitrary-text spreadsheet escaping (`publication/insertion_context.py:17–23,48–64`). Fresh probes preserved both exact strand enums and protected a `+source` text identifier. Gapped alignment strings are not TSV fields here. No cross-module escaping repair is warranted.

`input-sequences.json` replays original normalized target DNA (`publication/sequence_ports.py:42–55,90–105`), and the frontend selects typed sequence packets rather than result reports (`useSequenceHandoff.js:17–26`). A future derived IS/flanked-locus/protein port needs an actual consumer, versioned source/hash/coordinate identity, clipping and eligibility policies, and explicit orientation semantics. Family similarity or transposase strand cannot establish RNA homology or acquisition orientation.
