# Council 09 — SpacePHARER

Reviewed 2026-10-14 by three members covering author intent/native computation, references/output/handoffs, and platform boundaries. Independent reviews were followed by explicit cross-challenges and rebuttals; both specialists completed their reviews. The clean scientific checkout matches **2.1.1**, commit `4f264252846acef7e0d291209e3e5e3f6faf306c` (`tools/tools.lock.json:108–115`). This report covers `spacer_association` only. No implementation, installed-runtime changes, downloads or production operations occurred; current native source was built into a disposable temporary directory.

## Four verdicts

1. **Author-intended integration: passes within explicit grouping policy.** The combined protein/nucleotide method and native empirical controls remain intact. User groups preserve distinct scoring/support identities; calibration uses score populations across the entire submitted run. Arbitrary grouping does not acquire biological validity from computational parity.
2. **Required data: the operator-owned target/control reference is mandatory; broader coverage needs evaluation.** Construction and immutable identity gates are sound. Reversed translated ORFs are a supported null strategy, so a separate eukaryotic-virus reference is not additionally required. This review does not certify a deployed collection or broad-reference biological FDR.
3. **Compact scientific output: sufficient and appropriately qualified.** Complete groups, occurrences/origins, reference scope, calibration state, scores and source-bound alignments survive publication. A stage label overstates calibration, and explanatory wording should distinguish group separation from run-wide calibration.
4. **Downstream readiness: ready as a spacer consumer and evidence endpoint.** Detection/CCTK spacer handoffs preserve occurrences. Association evidence cannot automatically become verified host identity, target-genome input, homology or transcription orientation. No mandatory derived-evidence port is missing.

## Author intent and scientific preservation

The [authors’ 2021 paper](https://pmc.ncbi.nlm.nih.gov/articles/PMC8504623/) defines the query set as spacers from a prokaryotic genome, combines translated and nucleotide matches, aggregates support and estimates error using null matches. Its benchmark does not establish present sensitivity or achieved FDR for arbitrary user groups and new references. The [upstream manual](https://github.com/soedinglab/spacepharer#creating-databases) documents inverted translated ORFs as a control option.

The current wrapper invokes `createsetdb --extractorf-spacer 1` and `predictmatch` with matched target/control databases, detailed nucleotide alignment output and disabled PAM reporting (`tools/SpacePHARER/python/spacepharer/pipeline.py:81–115`). Native translated search, nucleotide refinement, best-hit aggregation and control search remain in `data/predictmatch.sh:27–122`. Geometric e-value combination and empirical-tail arithmetic are explicit in `src/core/Statistics.h:37–43`. The order-sensitive fallback (`:17–35`) and final matching nucleotide-row selection (`src/util/CombineProtNuclAln.cpp:84–96`) deliberately preserve historical behavior. They must not be “simplified” without a separate scientific revision.

One native FASTA is created per user group. Exact sequences are searched once within each group, then projected back to every occurrence; reverse complements and cross-group sequences are not collapsed (`pipeline.py:47–75`; `report.py:102–113`). This is a documented wrapper policy, while the native CLI retains historical supplied-record behavior (`README.md:96–103`). A contig is not necessarily a complete host genome, and pooling unrelated hosts changes the author-intended query unit.

**Group separation does not mean independent group calibration.** One native invocation handles all group FASTAs. `FilterMatchbyFdr.cpp:27–57,74–105` collects their target/control scores into shared populations. Changing batch composition can therefore change calibration. The native algorithm requires an estimable score curve, not merely two populated databases (`:154–199`). Missing calibration remains `unavailable`, or `not_run` for wholly unsupported inputs; missing FDR remains null. A retained boundary row above the requested FDR is a candidate, not an accepted association (`report.py:48–64`). Combined scores are not probabilities.

API admission requires a provisioned reference and explicit grouping (`backend/src/crispr_web/service.py:121–122,176–177`). `per_source` groups by `(source_id, source_sha256)` and requires origins for every occurrence (`exchange.py:167–187`). Integration bounds inputs, invokes an operator-owned command shell-free and validates output (`Integration/crispr_integration/association.py:221–299`). The independent backend gate checks hashes, partitions, duplicate projection, status/count semantics and oriented alignment reconstruction without importing Integration or rerunning scientific scoring (`backend/src/crispr_web/execution/validation_association.py:94–289`).

## Reference scope, comparability and expansion

Preparation builds both indexes from the same sequence database, changing only `--reverse-fragments` between target and control (`tools/SpacePHARER/python/spacepharer/reference.py:137–153`). The operator acquisition script freezes UID enumeration, verifies fetched identities, records exclusions and retains exact-sequence accession aliases with RefSeq preference (`scripts/prepare_phage_reference.py:80–112,157–188,355–427`). Its complete-genome-title, genomic-DNA, unsegmented and 1 kb–5 Mb policy excludes partial, RNA, segmented and other unsupported records (`:314–335`). [NCBI Virus documentation](https://www.ncbi.nlm.nih.gov/labs/virus/vssi/docs/help/) describes the underlying GenBank/RefSeq resource. This is a bounded collection policy, not comprehensive coverage of phages in nature.

Both platform reference gates verify manifest/index/catalogue bytes and reject unsafe paths; matched target sequences are loaded into an eight-genome cache, checked against sequence digests and used to reconstruct alignments (`Integration/crispr_integration/association_reference.py`; independent `backend/src/crispr_web/execution/validation_association_reference.py:57–87,90–204,207–291`). The 100,000-genome/10-Gb ceilings are engineering limits. They neither recommend that size nor prove its runtime cost is acceptable.

A useful extension could be a quality-filtered uncultivated DNA-virus collection. The [IMG/VR v4 primary publication](https://academic.oup.com/nar/article/51/D1/D733/6833254) describes genome-quality estimates and metadata, and its [official portal](https://genome.jgi.doe.gov/portal/IMG_VR/IMG_VR.home.html) provides high-confidence subsets. Such expansion requires compatible sequence identities, contamination/completeness rules, recorded exclusions, duplicate/near-duplicate policy, matched control rebuilding and scientific evaluation. Combining overlapping repositories without redundancy assessment changes the score population and evidence weighting.

Acceptance for an expanded reference should bind its accession/version/digest manifest and target/control construction, then evaluate representative host–phage positives and justified negatives across covered taxa, near relatives, short/ambiguous inputs and different group sizes. Report precision/recall or false-discovery behavior with counts and uncertainty, separating benchmark overlap from independent evidence. Compare the unchanged reference and algorithm, and measure memory, disk, search/index time, cancellation and concurrent-job cost. A broader scope label, checksums, native parity or an `estimated` receipt cannot substitute for that evaluation. No additional data were downloaded or biologically benchmarked here.

## Compact results and downstream contracts

Public JSON retains reference identity/scope/source, requested FDR, run-level receipt, complete group membership, supported/unique counts, unsupported IDs, associations and every sequence-bound support (`backend/src/crispr_web/summaries/association.py:8–82`). Compact `result.json` adds every submitted occurrence and preserved origin, explicitly qualifying those annotations as unverified host identities (`publication/compact/association.py:4–22`). The preview caps 100 associations and 50 hits with truncation flags; full exports reread complete validated evidence (`summaries/association.py:85–96`; `publication/association.py:9–22`). Bounded compact-export failure produces `complete:false`, not an empty scientific result (`publication/module_result.py:66–98`). Software versions/citations remain in provenance; private native working files are excluded from public bundles.

The UI preserves null calibration, explains scope and unsupported inputs, distinguishes candidates, and describes descending coordinates without inferring PAMs (`frontend/src/components/results/protospacer/AssociationResults.vue:42–64,83–95`). Its population explanation currently omits explicit run-wide scope, but neither JSON nor the results view asserts independent per-group calibration. The association TSV has six summary fields and no strand enum (`publication/association.py:23–30`); the cross-council `+/-` escaping defect does not apply.

Complete spacer-kind packets from detection or CCTK enter the association module; source metadata survives (`exchange.py:115–152`; `publication/sequence_ports.py:56–107`). `input-sequences.json` replays original input, while `result.json` is derived evidence. The frontend selects actual sequence artifacts for handoff, not compact results (`frontend/src/features/results/useSequenceHandoff.js:17–26`). Reusing original spacers for viral search is justified. Turning associations into target-genome downloads, verified hosts, RNA families or evolutionary arrays requires an additional biological selection/input contract and must not be inferred from similarity alone.

## Deliberation and concrete repairs

The references specialist challenged the initial shorthand that groups are “never pooled.” The science specialist confirmed separate score aggregation but pooled run-wide calibration. The chair traced this through public JSON and UI: there is one top-level receipt, and no per-group receipt or false numerical independence assertion. Both specialists agreed to clarify wording while preserving native arithmetic and all group/occurrence identities.

The chair challenged whether dropping native warning prose loses evidence. The only emitted wrapper warning describes unavailable FDR (`pipeline.py:146–149`); its state, null value and explanation survive publication. Both specialists rejected a current scientific-loss claim. They also rejected treating a broad reference or computational parity as validation of achieved biological error control.

**P2 safe wording/documentation fixes:**

- Replace the unconditional stage detail “calibrated target/control evidence” at `frontend/src/science.js:274` with neutral “target/control calibration.” Valid runs can be unavailable or not run.
- Explain beside the population counts (`AssociationResults.vue:52–54`) that they cover groups across this run, and clarify `docs/spacer-association.md:25`: membership/support stay separate, while empirical calibration uses run-wide target/control scores. Do not promise batch-invariant FDR.
- Update the documentation’s claimed lock version/link at `docs/spacer-association.md:6–8` to current 2.1.1/`4f264252…`; review `:132` without erasing valid 2.1.0 reference compatibility or historical verification.

Acceptance: current, unavailable and all-unsupported examples show accurate wording; group IDs, occurrence counts, scores, FDR/null values and downloads remain unchanged. Update UI expectations and run the relevant browser flow plus repository gate during implementation. Optional machine-readable calibration-scope metadata would require public schema/fixture propagation; it is unnecessary for the wording repair and must not alter the native receipt. No new scoring, deduplication or reference replacement is recommended as a safe engineering fix.
