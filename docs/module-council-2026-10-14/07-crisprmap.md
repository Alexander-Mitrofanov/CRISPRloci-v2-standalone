# Council 07 — CRISPRmap-v2

Reviewed 2026-10-14 by three members covering scientific intent, references/output/handoffs, and platform boundaries. Independent inspections were followed by an explicit challenge/rebuttal round. Scope is the hosted `repeat_map` mode and its relationship to the standalone tool. Version `2.1.0a2`, commit `4b35029a3600a983a7e3d0a63190377d60a31769`, matches the lock and clean tool checkout (`tools/tools.lock.json:88–95`). No implementation, reference downloads, runtime changes or production actions were performed.

## Four verdicts

1. **Author-intended integration: passes for the declared historical mapper.** The platform correctly runs the independent 2026 implementation's historical `classify` workflow. It does not reproduce Freiburg's original structural clustering or expose the standalone modern catalogue extension. These are distinct scopes, not silently missing steps in this workflow.
2. **Required/background data: no demonstrated missing historical asset; substantial optional coverage opportunity.** A validated 2013 reference exists locally. Missing family/motif annotations are genuine source missingness. Larger catalogues could improve sequence coverage but cannot supply authentic historical labels merely by adding sequences. Deployed reference identity was not inspected.
3. **Compact scientific output: strong machine-readable evidence; demonstrated frontend policy/truncation defect.** Native/public JSON retains uncertainty and tie evidence. The browser silently caps displayed alignments at 20 even when the native result legitimately reports more, and describes configurable settings using hardcoded defaults.
4. **Downstream readiness: compatible sequence reuse, limited derived-evidence integration.** Repeat sequences can feed typing and folding. Historical family/motif results are evidence, with no identified downstream module requiring a missing annotation port. They must not become Cas subtype, transcription-strand or homologous-array assertions.

## Scientific integration and validation

The [official Freiburg documentation](https://rna.informatik.uni-freiburg.de/Help.jsp?toolName=CRISPRmap) describes independent sequence/structure clustering and distinguishes the 2013 reference from the expanded, repartitioned 2014 release. The original [CRISPRmap study](https://doi.org/10.1093/nar/gkt606) and [CRISPRstrand study](https://doi.org/10.1093/bioinformatics/btu459) address these richer historical methods. The pinned implementation explicitly disclaims recreating LocARNA clustering, superclass inference and CRISPRstrand (`tools/CRISPRmap-v2/README.md:12–17`). Its modern catalogue is another separately documented workflow (`:19–27,57–73`).

Integration invokes local `classify`, with an operator-owned reference, at most 100 repeats of 200 bases, a 100,000-comparison reservation and a bounded deadline (`Integration/crispr_integration/repeat_map.py:45–76`). No request calls the historical web service. Reference acquisition is an explicit operator command; classify does not download data. Worker execution and the independent backend gate remain separate from API admission.

The native engine searches both recorded orientations using global unit-cost edit distance. An exact canonical lookup preserves every occurrence; nonexact queries retain all closest ties within the configured distance. Annotation consensus is calculated before applying `top_k`. A nonexact family is a candidate, while its motif is reference evidence; assigned values remain null. Exact conflicts and incomplete annotations also remain unassigned (`tools/CRISPRmap-v2/src/crisprmap/core.py:86–117,165–217`). Similarity is a length-normalized distance, not confidence. Reference-relative orientation does not identify transcription strand.

The backend independently binds reference bytes and canonical content, source records, policy, method, all closest ties, label conflicts, alignments, counts and stage completion (`backend/src/crispr_web/execution/validation_repeat_map.py:65–182`). It uses its own banded distance implementation rather than importing Integration/native validation. This is meaningful defense in depth; no new validation defect was demonstrated. Larger references must respect its 25,000-entry bound and the shared 100,000-comparison budget. A syntactically admissible large batch can exceed the conservative work budget; increasing reference size without evaluation would increase such failures.

## References and expansion

Both specialists inspected the local historical reference. It contains **3,527 unambiguous records, 2,031 canonical sequence groups, 1,258 null family labels and 1,713 null motif labels**, in namespace `crisprmap-2013-v1`. Its file SHA-256 is `6fef7239fd6b2e7f6a08a17d1c6caa13adb182c5c007e74aaa5d63963f20b55e`. The importer pins original URLs, bytes and hashes, binds labels to records and preserves missing annotations (`tools/CRISPRmap-v2/scripts/fetch_legacy.py:22–38,64–78,132–145`). Config requires a reference path and digest together, rejects symlinked paths, and requires a release-pinned tool (`backend/src/crispr_web/config.py:492–501`). Local availability does not establish which reference a deployment uses.

The official documentation lists **3,527/40/33** repeats/families/motifs for 2013 and **4,719/24/18** for 2014. This is a changed partition, not an interchangeable vocabulary. A complete 2014 reference was not recovered among checked assets; this review does not establish global unavailability. Any recovered release needs a distinct namespace, source/label verification and separate evaluation. Synthetic `examples/reference.json` labels have no biological meaning (`tools/CRISPRmap-v2/README.md:52–55`); passing release gates with that fixture establishes mechanics only.

The strongest developed expansion candidate is the tool's existing modern occurrence catalogue. Its prior release report records **2,175,735 searchable canonical groups**, an approximately **8.25 GB** catalogue and a separate index (`tools/CRISPRmap-v2/benchmarks/modern-20261001/RELEASE_REPORT.md:21–35`). These are previously recorded upstream results, not freshly verified hosted assets. The full scientific files are not present in the checked source distribution (`:95`). Its MAP2 components are operational sequence groups, with explicit chaining and quality tiers; they do not inherit historical family/motif labels (`tools/CRISPRmap-v2/docs/MODERN_REFERENCE.md:37–97`).

The recorded exact/RC-purged benchmark covered 66.1% of 1,000 sampled held-out sequences, compared with 18.5% using the historical reference. This motivates evaluation, not a claim of improved family accuracy: the report acknowledges residual relatedness, unknown detector/reference overlap and absent independent modern labels (`RELEASE_REPORT.md:53–70`). The [CRISPRCasdb primary publication](https://pmc.ncbi.nlm.nih.gov/articles/PMC7145573/) describes downloadable repeat collections and evidence levels, but those observations likewise do not supply historical family/motif truth. A broader source can improve occurrence coverage while adding redundancy and detector error.

Modern catalogue support therefore requires a separate adapter and contract for catalogue/index identity, optional groups, occurrence provenance, quality tiers and bounded indexed retrieval. It is not a replacement `reference.json`. Neither new catalogue import nor threshold/model changes belong in the immediate engineering repair.

## Output and interoperability

The public report keeps source sequence/hash, exact/near/no-hit/unsupported status, best distance, total/reported tie counts, missing/conflicting label evidence and bounded alignments (`backend/src/crispr_web/summaries/repeat_map.py:6–21`). Compact `result.json` deduplicates reference metadata and retains distance, orientation, alignment and annotation evidence (`publication/compact/search.py:98–138`). Software/citations remain available through provenance; their absence from compact results is not evidence loss. The concise cautions about no-hit novelty, near assignments and orientation are scientifically useful.

Three separate limits must be distinguished. Native `top_k` caps reported hits after all-tie annotation calculation. Backend `max_rows` caps query previews and sets `results_truncated`. Finally, `frontend/src/features/results/model/repeatMap.js:39–41` applies an additional per-query 20-hit slice, while `:36` copies only native `hits_truncated`. A fresh Node probe supplied 30 reported ties with `top_k=50` and native `hits_truncated=false`: the browser model retained 20 hits, still marked false, and discarded policy. Full public JSON remained intact. API options permit top-k 1–100 and distance 0–3 (`backend/src/crispr_web/scientific_options.py:90–93`), but `RepeatMapResults.vue:39–40,76–78` describes three edits and twenty displayed hits regardless of effective settings.

This is misleading presentation, not native tie loss. A bounded UI cap is reasonable if its displayed count and truncation are explicit. The public TSV is intentionally a compact query/annotation table (`backend/src/crispr_web/publication/repeat_map.py:16–23`). It has no strand field; the prior councils' typed `+/-` escaping defect does not apply here. Alignment orientation remains `forward`, `reverse` or `both` in JSON.

The sequence exchange contract accepts repeat-kind DNA for mapping, typing and folding (`backend/src/crispr_web/exchange.py:34–36,115–152`). `input-sequences.json` republishes original normalized input and immediate origins (`publication/sequence_ports.py:42–104`); it is not derived mapping evidence. Compact `result.json` is not a submission port. Comparing repeat typing and thermodynamic folds is useful, but neither can automatically confirm historical motif identity. Historical labels/MAP2 components must not create homologous groups for SpacerPlacer/evOr or RNAalifold, nor select transcription orientation.

## Council deliberation and action criteria

The science member initially described a pass for historical mapping and partial support for the complete standalone tool. The data member challenged whether the unused modern catalogue meant missing required background data. Resolution: no; hosted scope is historical mapping. Modern support is an optional, separately validated capability. The chair challenged whether a larger annotated source could repair null labels. Both specialists rejected that inference: unrelated annotation vocabularies and occurrence metadata cannot fill historical family/motif values.

The chair then challenged the claim of silent evidence loss. Both specialists reproduced the frontend discrepancy but narrowed the finding: public/native JSON and all-tie annotation consensus are intact; browser-only truncation and method text are misleading. Naming was also challenged. The UI's “CRISPRmap v2” and sole original-site reference can blur the independent implementation with Freiburg's 2014 version, but the UI does not claim structural clustering runs (`frontend/src/science.js:96–104`; `components/shell/ReferencesSection.vue:154–163`). This is attribution ambiguity, not a demonstrated algorithm error.

**P1 engineering:** carry effective distance/top-k and reported-hit count through normalization; either render the bounded native maximum of 100 or explicitly identify an independent UI preview cap. Derive preview truncation from actual displayed/reported counts and preserve native all-best-tie semantics. Acceptance: top-k 1/50/100, distance 0/1/3, and more than 20 ties render truthful policy/counts; missing policy remains unknown; full downloads remain unchanged. Add focused model/component and browser checks.

**P2 clarity:** identify the independent historical-reference mapper and link its pinned implementation beside the original paper, consistent with `tools/CRISPRmap-v2/CITATION.cff:2–9`. Keep this concise rather than adding repetitive warnings.

**Separate scientific evaluation:** any modern catalogue integration needs pinned compatible manifests/assets, provenance/quality separation, performance and resource-failure measurements, overlap-aware coverage evaluation and explicit absence of calibrated family/motif accuracy. Do not merge historical namespaces or infer orientation/subtype from similarity.

## Fresh verification and limits

Chair checks: native `test_core.py`, `test_reference.py`, `test_io.py`, `test_cli.py`, `test_legacy_import.py`, `test_legacy_benchmark.py`: **86 passed** in the tool environment. Backend `test_repeat_map.py`, excluding HTTP/detection-JSON cases: **15 passed, 2 deselected**. Frontend `repeat-map-ui.test.js`: **3 passed**. The data member's repeat connectivity subset passed **88 tests, 218 deselected**; suites overlap and counts are not unique coverage. An initial backend invocation needed the repository's documented `--import-mode=importlib`; an initial native run in the backend environment lacked installed `crisprmap`. Correct-environment reruns passed without changes.

The science member additionally ran the installed native mapper on the stored original 16-query input against the real 2013 reference under Integration's limits: **14 exact, 2 near, 1,980 comparisons, ten unanimous family assignments and ten motif assignments**. Conflicts/missingness remained explicit. This is fresh historical retrieval, not an original-executable rerun or new biological validation. No production inspection, modern full-corpus rerun, browser E2E or full platform gate was performed by this council. No blocker prevents the scoped presentation repair.
