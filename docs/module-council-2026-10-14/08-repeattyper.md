# Council 08 — RepeatTyper

Reviewed 2026-10-14 by three members covering author/model intent, references/output/handoffs, and platform boundaries. Independent inspections were followed by an explicit challenge/rebuttal round; both specialists completed their reviews. The clean tool checkout matches version **2.0.1**, commit `d55ebf535f21591d44a0229fd809795ddc330cda`, in `tools/tools.lock.json:98–105`. This is a report-only review of `repeat_type`: no implementation, model/data downloads, runtime changes or production operations.

## Four verdicts

1. **Author-intended integration: passes for the frozen repeat classifier.** Native computation preserves the upstream features, model, 37 labels and prediction iteration range. A demonstrated reverse-complement consistency gap remains in both platform validation gates; it does not establish naturally incorrect native inference.
2. **Required/background data: complete for inference; evaluation provenance needs work.** Bundled model and label bytes suffice. The package does not bind exact training records, partitions or calibration evidence to those bytes. Broader datasets are candidates for evaluation, not necessary runtime downloads or automatic replacements.
3. **Compact scientific output: sufficient and honest.** Per-occurrence evidence, missingness, policy, model identity and preserved origins survive publication. The UI correctly describes scores as uncalibrated closed-set outputs. Documentation has two small, demonstrable inaccuracies.
4. **Downstream readiness: ready for repeat-sequence reuse, with biological limits.** Repeat DNA can feed folding, reference mapping and reclassification. A subtype prediction cannot establish a homologous RNA/array family, transcription orientation or a complete Cas system. No missing mandatory derived-evidence port was identified.

## Author intent and model preservation

The [original author publication](https://pubmed.ncbi.nlm.nih.gov/33275853/) describes repeat-based subtyping as useful for orphan and distant arrays. Its headline 98.6% median benchmark concerns the complete CRISPRCasTyper system; it is not a calibrated accuracy claim for this extracted classifier. The independent package clearly declares repeat-only scope and upstream attribution (`tools/RepeatTyper/README.md:3–7,79–87`).

The frozen representation has 136 canonical tetranucleotide counts, GC fraction and length: 138 sorted float32 columns, preceded by the upstream zero sentinel row (`tools/RepeatTyper/src/repeattyper/features.py:14–31`). Prediction uses exclusive iteration range `[0,41)` and first-index argmax (`inference.py:32–44`), matching the frozen upstream implementation (`tests/upstream/xgb.py:129–147`). Changing the upper endpoint to 42 because `best_iteration` is 41 would alter the preserved algorithm, not repair an established bug. The [upstream release history](https://github.com/Russel88/CRISPRCasTyper/releases) documents earlier feature/model changes and incompatibility, reinforcing the need to version representation and model together.

Model loading verifies provenance and resource hashes, class order, feature count, objective and best iteration before inference (`model.py:14–37`). The model digest is `f9170b07805d1bb89fa1c02cfb861836e42498738e458f5e9e6db181dfcbe57a`; `data/provenance.json:2–55` binds the CRISPRCasTyper 1.9.0 commit, wheel, label file and 37-class vocabulary. Broader Cas-system coverage advertised upstream does not expand these outputs. Generic V-F in upstream prose is not a missing local label that can simply be appended.

Integration accepts at most 1,000 DNA occurrences of 1–200 bases, creates normalized input, invokes the operator-owned command shell-free and validates completion/model/input/policy identity (`Integration/crispr_integration/repeat_type.py:63–129`). The backend independently checks original source bindings, bounded records, finite scores, allowed labels, statuses, duplicate consistency and stage identity (`backend/src/crispr_web/execution/validation_repeat_type.py:65–120`). Neither gate imports the other's validator or reruns the model. API admission requires a provisioned release identity (`backend/src/crispr_web/service.py:123–124`).

The default threshold is 0.75, with equality accepted. Below threshold, `prediction` is null while `winner` and `native_score` remain available; ambiguous IUPAC inputs are unsupported with null winner/score (`inference.py:46–66`). These are abstention and input-support policies, not detection of a novel family. Canonical features make unambiguous reverse complements identical to the classifier; no strand can be inferred.

## Data scope and useful expansion

There is no missing external inference reference. The useful missing evidence is a training manifest tied to the exact model: original sequences, label derivation, taxonomy, canonical deduplication, partitions and evaluation/calibration records. Absence from this package does not prove the authors never evaluated the model, nor does software version establish its training date.

The [authors' README](https://github.com/Russel88/CRISPRCasTyper#updated-repeattyper-models) describes larger crowdsourced models and training reports, and historically uneven per-label accuracy. Those resources justify investigating coverage; they do not identify a superior compatible replacement or measure the present pinned bytes. The council did not verify a newer downloadable model's contents or availability.

Two useful evaluation sources are repeat/locus observations from [CRISPRCasdb](https://academic.oup.com/nar/article/48/D1/D535/5590637), which exposes repeats and Cas context, and deliberately selected newer bacterial/archaeal genomes from [NCBI RefSeq](https://www.ncbi.nlm.nih.gov/refseq/). These are candidate sources, not ready-made ground truth. Their sequence identity, assembly quality, taxonomic representation, annotation conflicts and overlap with training material require review. Broadening collection size alone can amplify redundant organisms and circular labels.

First recover the training identities if possible. Partition exact and reverse-complement duplicates together, then keep related repeat families and genomes/clades together across training and evaluation. Curate labels from independent protein/locus evidence, preserving discordance and unknown assignments; do not label new examples from RepeatTyper itself. Include rare supported classes, absent classes, short/atypical repeats and taxonomic holdouts. If training identities remain unavailable, explicitly leave benchmark independence unproven.

Evaluate per-class confusion and precision/recall, threshold precision-versus-coverage, and high scores on out-of-vocabulary examples, with sample counts and uncertainty. A new model needs pinned provenance, label mapping, feature compatibility, runtime/memory measurements and comparison against the unchanged frozen control. Dataset curation and training consume resources beyond the small inference runtime; no such work was authorized here.

A fresh native illustration makes the limitation concrete. Of 45 frozen upstream fixture records, nine identifier prefixes are outside the 37-label vocabulary. Fixture `IV-C_2` (`tests/upstream/repeats.fasta:41–42`) receives I-B with score **0.8087520003318787**, hence `predicted` at 0.75. This demonstrates that an externally labelled, absent class can score highly. Fixture identifiers are not independently adjudicated biological truth, and these potentially overlapping fixtures cannot supply a new accuracy estimate (`README.md:63–69`).

## Output and downstream contracts

Public JSON retains sequence/hash, status, prediction, native winner/score and reason for every occurrence, plus model identity/labels, threshold and counts (`backend/src/crispr_web/summaries/repeat_type.py:5–11`). Bounded summaries advertise preview truncation; full exports reread complete validated evidence (`publication/repeat_type.py:8–20`). Compact `result.json` joins preserved origins by occurrence ID (`publication/compact/repeat_type.py:4–10`). Software/citation details remain available in provenance. The native report itself only emits the winning class/score; absence of a full 37-score vector from compact output is not publication loss.

The browser explicitly warns about uncalibrated scores, unfamiliar families scoring highly, and absence of system/strand inference; unknown and unsupported rows remain distinct (`frontend/src/components/results/repeats/RepeatTypeResults.vue:36–74`). No threshold wording or missingness defect was demonstrated.

Complete repeat-kind DNA packets are accepted by typing, mapping and folding (`backend/src/crispr_web/exchange.py:34–36,115–150`). `input-sequences.json` replays normalized original input and immediate origins (`publication/sequence_ports.py:42–104`); it is not newly derived evidence. The UI selects actual sequence packets rather than `result.json` (`frontend/src/features/results/useSequenceHandoff.js:17–26`). Origin metadata remains provenance supplied through the contract, not a fresh server verification of historical ancestry.

Subtype agreement can help users compare hypotheses with Cas annotations, historical mappings and folding results. It cannot automatically create homologous RNA families for RNAalifold, related arrays for SpacerPlacer/evOr, or a transcription direction. Those analyses require their own biological justification and input contracts. The TSV contains no `+/-` scientific enum, so the cross-council strand-escaping defect does not apply here.

## Deliberation, demonstrated repairs and acceptance

The chair challenged the apparently complete validation with a cheap model invariant. Both specialists derived exact reverse-complement equality from canonical counts, unchanged GC and length, while rejecting backend model re-execution. A fresh native pair, `AACTCCCTAGGAGGGAGTAGAAG` and its reverse complement, produced I-A/**0.9230033755302429** for both. Changing only the second winner/prediction to I-B and score to 0.9 still passed Integration and returned backend status `completed`. Both caches currently key only by literal sequence (`Integration/crispr_integration/repeat_type.py:90–92`; `backend/src/crispr_web/execution/validation_repeat_type.py:114–116`). This is a demonstrated integrity gap under contradictory output, not evidence of native misclassification.

**P1 bounded engineering:** independently compare winner/score for verified ACGT reverse-complement partners in each gate, using a canonical sequence key without importing scientific code or executing inference. Acceptance: unchanged native pairs pass; differing winners or scores fail in each gate; palindromes, repeated occurrences and threshold boundaries remain correct; ambiguous IUPAC retains existing null semantics without cross-group inference. Keep literal `distinct_classified_sequences`, all status counts, sequence hashes, occurrence order, origins and model bytes unchanged. This adds bounded linear work within the existing input limits.

The science specialist challenged transferring historical accuracy figures to this model; the output specialist narrowed the missing-data verdict to absent package-bound evaluation evidence. Both rejected mandatory subtype-to-homology handoffs. Resolution: preserve the honest current output, and separate model/data evaluation from safe gate hardening.

**P2 documentation:** update `docs/repeat-typing.md:6` from the old 2.0.0 revision to locked 2.0.1. Correct `:35–36`, which says JSON/TSV retain model identity, labels and threshold: JSON does, while TSV intentionally contains seven occurrence fields (`publication/repeat_type.py:15`). Acceptance is accurate version/link and export descriptions; no TSV schema expansion or new scientific policy is needed.

## Fresh verification and limits

Current checkout source was explicitly imported using existing isolated RepeatTyper dependencies, an isolated temporary working directory and disabled bytecode writes. The standalone suite initially had **67 passes and one dependency failure** because the frozen upstream oracle imports pandas. Rerunning that exact parity test with existing local pandas support passed: numpy **2.3.4**, XGBoost **3.1.1**, pandas **3.0.6**. Thus all **68 standalone tests** passed across the two runs, including full upstream score-matrix equality on frozen examples, 100 seeded sequences and reverse complements. No dependencies were installed.

`backend/tests/test_repeat_type.py`, using a temporary current-source native launcher, passed **20 tests**, with the HTTP-worker test deselected. `frontend/tests/repeat-type-ui.test.js` passed **3 tests**; the output specialist also passed **11 focused sequence-handoff tests**. The specialist's repeated UI run overlaps that count. The reverse-complement forgery probe and fixture closed-set illustration were fresh native/contract observations, not new biological performance measurements.

No browser E2E, full platform gate, deployment inspection or independent biological benchmark was run by this council. The parent review owns the full gate. Existing installed runtime source was not assumed current, and these tests do not certify a deployed release. No blocker prevents the scoped engineering/documentation repairs; missing training provenance limits claims about biological generalization and future model upgrades.
