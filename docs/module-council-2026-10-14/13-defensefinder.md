## Four verdicts

**1. Author-intended integration: supported for the declared historical, bounded repertoire task, with configuration-isolation and independent-validator gaps.** The underlying method combines protein-profile evidence with system architecture rules; a profile match alone is not a complete defense system ([DefenseFinder method paper](https://doi.org/10.1038/s41467-022-30269-9)). The derivative preserves these distinctions rather than presenting a functional assay. `tools/DefenseFinder-v2/defense_context/pipeline.py:23-35,101-124,230-255` pins Pyrodigal 3.7.1 meta mode, MacSyFinder 2.1.4, HMMER 3.4, 20 records/2 Mb, coverage-profile 0.4, and linear topology. It executes six model directories, `DefenseFinder_1` through `_5` plus `RM`; these are not six biological defense families.

Gene calling is separate per submitted contig, with generated replicon IDs and ordered proteins. One-based inclusive CDS coordinates, translation tables, partial boundaries, oriented original-DNA hashes, and exact native proteins are retained, including ambiguity-derived X residues. Gembase IDs preserve replicon separation, consistent with [MacSyFinder's documented convention](https://macsyfinder.readthedocs.io/en/latest/user_guide/gembase_convention.html). Native global FASTA rank differs deliberately from exported local `position`. Shared proteins retain every component assignment; only within-system membership is deduplicated. Equal-score profile ties retain the first family/path traversal winner (`pipeline.py:152-227`).

Integration invokes an operator-owned command without a shell and checks source translations, system membership, counts, finite scores, and policy identity (`Integration/crispr_integration/defense_context.py:25-104,107-130`). The backend independently reconstructs translations and reparses native evidence without importing Integration (`backend/src/crispr_web/execution/validation_defense_context.py:1-3,61-155`). The separate Cas stage and coordinate-only nearest-cassette join do not run CasFinder or merge its classifications into DefenseFinder results (`Integration/crispr_integration/context_annotations.py:4-24`; `backend/src/crispr_web/summaries/context_annotations.py:8-38`).

**2. Required data: present and identity-verified for model 1.2.3; expanded coverage is an evaluation project.** Fresh manifest inspection found 832 assets: 589 profiles, 241 definition-tree files (239 XML and two compressed housekeeping files), LICENSE, and metadata. Asset counts must not be described as biological family counts. The exact model commit is `5bdb41257fc7234fb8c3b70e3d362c52541860dd`; manifest SHA-256 is `bb4dc6de8dfce9179e5d14b1649d1af1e27ca5b0e14840787e883aa46a8d7348`. Fresh native verification passed. Operator provisioning checks exact files and hashes, with bounded extraction; jobs do not download references (`scripts/runtime/context_tools.py:55-114`; `pipeline.py:84-98`). No missing required profile bundle was demonstrated.

The locally verified pinned [1.2.3 metadata](https://github.com/mdmparis/defense-finder-models/blob/1.2.3/metadata.yml) and retained model LICENSE agree on GPL-3.0. In contrast, freshly retrieved [3.1.0 metadata](https://raw.githubusercontent.com/mdmparis/defense-finder-models/3.1.0/metadata.yml) declares both GPL-3.0 and CC BY-NC-SA 4.0. That conflict is not resolved by choosing whichever declaration is convenient. The repository documents exclusions for intervening releases; this council did not freshly audit every release between 1.2.3 and 3.1.0. Keep source and third-party notices with the minimal distribution (`tools/DefenseFinder-v2/CRISPRLOCI.md:8-31`; `setup.py:12-22`).

Broader models may improve repertoire coverage, but require an explicit rights decision, pinned asset identity, compatible engine/rule semantics, a versioned scope change, and representative positive/negative/fragmented-genome evaluation. Measure changed calls, false positives, memory, time, and output size. Neither larger coverage nor optional embedding models should be downloaded automatically. Current no-call results mean no system call under the submitted-sequence/model scope; they cannot establish genome-wide biological absence or inactivity.

**3. Compact scientific output: complete and useful; two frontend fidelity repairs remain.** `public_report` retains sources, complete gene/protein records, systems, assignments, profile hits, model identity, policy, and separate Cas proximity (`backend/src/crispr_web/summaries/defense_context.py:4-19`). The compact exporter deliberately retains these collections (`backend/src/crispr_web/publication/compact/defense_context.py:4-6`). This agrees with `docs/module-results.md:62,86-102`; detail alone is not clutter. Versions and citations can remain in provenance without scientific data loss.

A fresh preview-cap-1 probe showed one of two components in the preview, while `defense-context.json` and complete `result.json` retained 42 genes, one system, two components, and five hits. Preview truncation therefore does not truncate downloads. The public TSV contains exactly `id`, `source_id`, `type`, `subtype`, `start`, `end`, `wholeness`, `score`, and `gene_ids` (`backend/src/crispr_web/publication/defense_context.py:27-55`). It has no strand field, so other councils' escaped `+`/`-` TSV defect does not apply here. Preserve protection for arbitrary formula-like text.

The view states that model 1.2.3 and submitted sequences are assessed, CasFinder/newer models are excluded, and calls do not establish activity or cooperative immunity (`frontend/src/components/results/annotations/DefenseContext.vue:29-52`). Model wholeness is completeness relative to rules, not a calibrated probability of biological function.

**4. Downstream readiness: genomic input replay is ready; derived findings are evidence, not submission ports.** `defense_context` accepts the typed `target` port (`backend/src/crispr_web/exchange.py:18-39`). `input-sequences.json` replays normalized original inputs, preserving available origins; the frontend offers compatible follow-up modes from this artifact (`backend/src/crispr_web/publication/sequence_ports.py:38-105`; `frontend/src/features/results/useSequenceHandoff.js:17-32`). Neither `result.json` nor `defense-context.json` is a derived protein/neighborhood handoff. Adding such a port requires a source/interval/sequence contract, orientation, eligibility, and provenance; coordinate proximity must not manufacture homology or functional cooperation. Its absence is not a blocker for the existing replay workflow.

## Demonstrated engineering actions and acceptance

**P1 — isolate effective MacSyFinder configuration.** A fresh exact-source scan from a clean private temporary working directory used unchanged pinned models and an inherited `MACSY_CONF` pointing to a temporary file containing `[score_opt]` and `mandatory_weight = 3`. The positive RM system score changed from **2.0 to 6.0**, while counts **42/1/2/5**, model identity, and exported policy stayed identical. Integration accepted the changed report. This follows a real inherited-environment route: worker copies its environment (`backend/src/crispr_web/worker.py:479-490`); runtime wrappers clear Python import overrides but not MacSyFinder configuration (`scripts/provision_tools.py:124-134`); Integration inherits it (`runner.py:155-161`). The [MacSyFinder configuration precedence documentation](https://macsyfinder.readthedocs.io/en/latest/user_guide/FAQ.html#what-are-the-rules-for-options-precedence) agrees with inspected 2.1.4 `macsypy/config.py:177-243`. Explicit command flags cover only some effective parameters.

Acceptance: add a DefenseFinder-local preflight matching pinned MacSyFinder resolution: selected virtualenv/system or `MACSY_CONF` file, user-home configuration, current-directory configuration, and consumed model configuration. Reject existing undeclared configurations, including symlinks, without opening their contents. This deliberately declines custom settings; it must not change the worker environment for other tools. No ignore-config option was found; an empty/partial `--cfg-file` is insufficient because settings accumulate. Poisoned `MACSY_CONF` and home-config tests must reject before analysis; clean positive/negative/multisource controls must preserve score 2.0 and established counts. Propagate any native-source correction through tool pin, package, and release identities. Do not retune thresholds or change model bytes. Provisioning rejects extra files and release inventories hash installed assets (`scripts/runtime/common.py:134-158`), but external ambient configuration remains outside them. No deployed contamination was observed. An added package-root `model_conf.xml` did not alter this run; that experiment is not a demonstrated scoring defect.

**P1 — independently bind native rank and length.** Fresh temporary fixture mutations changed `best_solution.tsv`'s `hit_pos` or `hit_seq_len`, and the HMM extract's rank or protein-length field (zero-based indexes 2/3), individually to `999999`. All four mutated cases passed backend validation; the unchanged baseline passed too. The exact pinned tool's `collect` rejected each mutation as a native gene-identity mismatch. Backend `_native_matches` currently checks IDs/replicons and selected scores but ignores those four fields (`validation_defense_context.py:158-198` versus `pipeline.py:152-164,182-191`). This proves an independent boundary fidelity gap, not an observed wrong displayed biological call.

Acceptance: independently enumerate global protein FASTA ranks and exact protein lengths; reject each altered native field while preserving all valid overlapping assignments and tie behavior. Include a multi-source regression: the second control contig has native system ranks **64/65** and exported local positions **22/23**. Comparing native rank with local `position` would introduce a bug. Keep validation bounded and independent; do not rerun scientific gene calling or scan references. Integration already validates the report while backend adds native-table checks; wholesale Integration duplication is unnecessary.

**P2 — preserve the numeric strand enum at the frontend boundary.** DefenseFinder emits integer `-1`/`1`; `defenseContext.js:35-42` passes these into the shared string-only helper at `contextValues.js:9`. A fresh Node probe returned null for both. The current component does not render strand, so this is latent model information loss. Normalize the documented integer enum locally to its correct direction, retain unknown/malformed values as null, and test both directions. Avoid changing string policies used by insertion, prophage, and locus views.

**P2 — communicate component-preview truncation.** Backend sets `components_truncated`, but `defenseContext.js:21-24` carries only system/hit flags and `DefenseContext.vue:85-96` supplies no component-limit notice. Propagate and render the flag, including cap zero/one tests. Full JSON, compact results, and downloads must remain complete and unchanged; this is a presentation repair.
