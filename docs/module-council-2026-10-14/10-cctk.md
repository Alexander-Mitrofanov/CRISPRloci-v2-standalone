# Council 10 — CCTK

Date: 2026-10-14. Scope: the public `array_compare` workflow and relevant retained standalone CCTK methods. This is a report only; no scientific source, runtime, reference, or production change was made. The chair reviewed platform admission, independent validation and publication; two specialists independently reviewed author intent/native science and references/output/handoffs, then exchanged challenges and rebuttals.

## Four verdicts

| Axis | Evidence-backed verdict |
| --- | --- |
| Author-intended integration | **Sound for observed comparison.** The adapter calls the real modernized `compare` command and preserves occurrence order, repeated spacer DNA, deletion slots and unknown strand. It correctly avoids presenting sharing as alignment, inferred acquisition history or phylogeny. |
| Required data / larger datasets | **No missing external reference blocks this workflow.** Submitted arrays and actual observed spacer DNA are the required evidence. BLAST databases and MinCED belong to optional standalone workflows. A larger relevant cohort may add comparison context, but there is no universal reference expansion that improves exact sharing. |
| Compact scientific output | **Complete comparison evidence, with one demonstrated metadata omission.** JSON preserves arrays, occurrences, policies, metrics, components and isolates, but carries uploaded scores/coordinates without the validated score and coordinate semantic fields. Restore those qualifiers. |
| Downstream readiness | **Ready for typed array replay and observed-spacer searches.** Original occurrences and origins survive export. Components do not establish homologous families, leader orientation, evolutionary eligibility or transfer. `result.json` remains evidence rather than a submission port. |

## Source identity and intended scientific scope

The inspected checkout is clean at lock-pinned commit `c2f619fb3dde849a7874ca243b487d2e6af062f8`, CCTK 2.0.2 (`tools/tools.lock.json:118–125`). `tools/CCTK/UPSTREAM.json:2–5` records the original Alan Collins repository and upstream 1.0.3 source identity. The [author's network documentation](https://crispr-comparison-toolkit.readthedocs.io/en/latest/content/network.html) expressly supports arrays detected outside CCTK and requires consistent spacer identities across arrays. The public adapter therefore does not need to rerun MinCED to make its input legitimate.

`Integration/crispr_integration/array_compare.py:162–209` constructs the native document from a pinned array map and actual spacer FASTA, then invokes `cctk compare --input … --outdir … --plot`. This is a supported command (`tools/CCTK/src/cctk/cli.py:33–43,69–80`). Scoped `(source_id, array_id)` identities are mapped to deterministic execution IDs; repeated observations retain their own occurrence IDs and ordinals. A deletion is explicitly null DNA, never a sequence placeholder. Admission refuses missing/ambiguous observed DNA and preserves unknown strand (`backend/src/crispr_web/array_exchange.py:76–184,187–234`).

Native parsing preserves every ordered slot (`tools/CCTK/src/cctk/comparison.py:81–121`). Exact DNA identity is the default; reverse-complement equivalence is an explicit alternative that changes the equality symbol only, leaving original DNA, strand and order unchanged. Distinct occurrences of the same sequence receive the same symbol without being collapsed. This matches the distinction between literal identity and sequence similarity in the [author's CRISPRdiff documentation](https://crispr-comparison-toolkit.readthedocs.io/en/latest/content/CRISPRdiff.html#sequence-blindness).

Sharing uses distinct spacer sets: `nshared = |A∩B|` and `Jaccard = |A∩B| / |A∪B|` (`tools/CCTK/src/cctk/sequence_operations.py:52–65,610–617`). Repetition does not inflate edge weight. Deletions enter neither set. Positive thresholded edges determine components; singleton and all-deletion arrays remain explicit isolates (`comparison.py:126–195`). A component can connect A–B–C even when A and C share nothing. It is not an all-pairs similarity group.

The native plot directly consumes supplied ordered symbol lists (`comparison.py:252–279`), while the public view explains equality, set metrics, source-forward order and uncertain orientation (`frontend/src/components/results/comparison/ArrayCompareResults.vue:52–69`). Neither is a structured alignment. The historical standalone toolkit additionally retains `crisprtree`, `constrain`, `evolve`, `blast`, `spacerblast`, `minced` and `quickrun` (`tools/CCTK/README.md:51–66`). The [author tutorial](https://crispr-comparison-toolkit.readthedocs.io/en/latest/content/tutorial.html) requires correct array orientation before `CRISPRtree` or `constrain`. Adding these methods to the public mode would require separate scientific evaluation and contracts, not correction of this adapter.

## Data, validation and practical limits

No learned model, external spacer catalogue or reference genome database is consulted by `compare`. The lock declares offline database-free comparison; provisioning installs the locked Python package stack (`scripts/provision_tools.py:343–350`). Optional MinCED and BLAST executables and associated references remain operator-provided standalone dependencies (`tools/CCTK/README.md:20–23`). Their absence from this execution path is intentional. Native tests exercise optional executable boundaries with controlled fixtures; this council did not establish current availability or biological performance of those external tools.

A defensible larger cohort would preserve source identities, sample scope, consistent observed sequence conventions and explicit equality policy. Additional arrays can change components and the apparent uniqueness of colored spacers. Near-match clustering, repeat-based orientation, inferred acquisition order or reference-derived homology would change the question and need evaluation; none should be silently added to exact sharing.

The Integration validator independently reconstructs symbols, arrays, counts, edges and components (`Integration/crispr_integration/array_compare.py:70–159`). The backend separately binds submitted map and FASTA bytes, reconstructs native input and recalculates the complete result without importing Integration validators (`backend/src/crispr_web/execution/validation_array_compare.py:17–172`). This bounded recomputation is appropriate for the observed metric, unlike re-executing an evolutionary model.

Capacity is layered. Native input permits 200 arrays, 500 slots per array and 10,000 total slots, subject also to complete output fitting 32 MiB (`tools/CCTK/docs/contracts.md:12–14`). Integration's shared FASTA reader admits at most 1,000 observed records (`Integration/crispr_integration/protospacer.py:57–69`). Public admission counts each observed occurrence against the service record limit, default 20 and environment-configurable up to 100 (`backend/src/crispr_web/service.py:143–166`; `config.py:397,647`); the UI explicitly explains this (`frontend/src/science.js:68–69`). These are genuine operational limits, not missing datasets. No silently truncated scientific report was demonstrated.

## Publication and implementable finding

`public_report` joins native comparison evidence back to uploaded source descriptors, scores, boundaries and coordinates (`backend/src/crispr_web/summaries/array_compare.py:8–69`). Browser previews cap arrays, slots and edges and mark truncation (`:72–89`). Complete `array-comparison.json` is built from full evidence; the compact projector copies it except its envelope (`backend/src/crispr_web/publication/array_compare.py:12–15`; `publication/compact/array_compare.py:4–10`). Native working files are private and excluded from the public ZIP; the public JSON is the complete scientific comparison export, not merely the browser preview (`backend/tests/test_array_compare.py:239–259`). Compact size failure produces `complete:false`, not partial data (`publication/module_result.py:81–99`).

**P2 — Restore coordinate and score semantics alongside exported values.** Input requires `coordinate_system="1-based-inclusive-source-forward"` and `score_semantics="uncalibrated-model-score"` (`backend/src/crispr_web/array_exchange.py:70–71`). `public_report` retains numerical coordinates and `model_score`, but its return object omits both qualifiers (`summaries/array_compare.py:29–42,46–69`). The compact envelope supplies no equivalent global fields (`publication/module_result.py:57–63`). A fresh native 2.0.2 fixture run with uploaded `model_score: 0.93` reproduced both omissions in `array-comparison.json` and `result.json.data` while retaining the score and coordinates.

The separate implementation should copy the validated fields into public comparison output and propagate the additive contract through compact schema/examples, documentation and tests. Preserve every score unchanged, including null, and retain the existing origin caveat. Document that category, model score and boundary annotations are supplied metadata: validating their shape does not verify their claimed producer or calibrate a score. Acceptance requires non-null and null-score fixtures to retain both exact semantic values in both exports, unchanged coordinates/counts/DNA/strand, exact `arrays.json` replay, and the unverified-origin caveat. Do not reinterpret 0.93 as a probability. This is a publication repair, not a scientific model change.

`arrays.json` exactly replays the submitted document (`publication/array_compare.py:16–28`). `spacers.json` exports original observed DNA occurrences with source/array/ordinal/coordinate origins, including repeated DNA and excluding deletion slots (`publication/sequence_ports.py:64–107`). It supports viral search or explicitly grouped spacer association. The fresh handoff probe preserved six observed records, two deletion slots in array evidence, three source groups, and unknown/minus strand. `input-sequences.json` is input replay; component membership is not a new sequence port. The public TSV contains identifiers and numeric metrics only; spreadsheet escaping of arbitrary identifiers is intentional, while exact identities remain in JSON. The other councils' controlled `+`/`-` TSV issue does not apply here.

## Council challenges, verification and remaining limits

The chair challenged report-size growth; the source specialist identified the documented native output budget and atomic-failure test, while the handoff specialist checked the smaller public occurrence limits. Resolution: no demonstrated reachable public defect; preserve bounded failure and explain capacities before larger-cohort exposure. An apparent raw-JSON browser limit mismatch was rebutted by actual serialized-request sizing in `useAnalysisForm.js:104–105,131–132`. Missing deletion-boundary display was rejected as data loss because full JSON retains it. A surrogate-identifier probe was rejected at backend admission. Conversely, the non-null score probe established meaningful qualifier loss, which is distinct from intentionally keeping software versions/citations in provenance. Both specialists completed the challenge round before synthesis.

Fresh checks used the existing isolated CCTK dependency environment with **current pinned source overriding the older installed package**; no environment was changed. Results: **160 CCTK source tests passed**, using the existing backend pytest package through an appended test import path; **19 native-backed backend comparison tests passed**, with the HTTP test explicitly deselected; **39 frontend array/handoff tests passed**. Native five-array probes produced JSON/TSV/PNG and passed Integration validation: duplicate-plus-deletion A, bridging B, C, all-deletion D and reverse-complement-only E gave exact edges A–B at 1/3 and B–C at 1/2, component A/B/C and isolates D/E. Threshold 2 gave five isolates; the alternative equality policy added expected E links without rewriting observations. Frozen legacy controls included 50 alignment/module cases and CRISPRdiff pixel parity.

**P3 — Refresh the stale browser availability assertion.** A fresh production frontend build succeeded into temporary storage. The existing `frontend/scripts/browser_array_compare.py` then ran against an approved local loopback server, but stopped at lines 103–105: it expects an unadvertised comparison link to be absent. Current `ModeSelector.vue:7–12` deliberately exposes methods with bundled examples, while `useAnalysisForm.js:155–156` still gates real submission on advertisement unless a matching precomputed example was explicitly loaded. Update this test to distinguish example visibility from execution availability: verify arbitrary valid array input cannot submit while unadvertised and that loading/running a matching offline example never enqueues live work; then advertise the mode and retain the existing desktop/mobile, evidence and protected-download assertions. This is test maintenance, not a demonstrated availability bypass. The later browser assertions were **not reached in this run**; do not record the whole browser flow as passed. The initial sandbox server attempt could not bind; approved local execution resolved that environmental obstacle and exposed the stale expectation. The owned temporary server was stopped.

The workspace private-data scan passed with zero findings. These are fresh synthetic/fixture and contract checks, not new biological accuracy measurements. The full platform gate, production readiness and installed release rebuild remain outside this report-only council. There is no reference-data blocker for the integrated scope.
