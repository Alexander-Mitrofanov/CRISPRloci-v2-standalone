## 1. Author-intended integration — qualified pass

The [author documentation](https://github.com/gamcil/clinker) presents clinker as a comparison/figure generator for small homologous gene clusters, warning that all-gene pairwise alignment scales poorly to whole genomes. The [primary paper](https://academic.oup.com/bioinformatics/article/37/16/2473/6103786) describes global protein alignment, cluster similarity incorporating synteny, Ward display ordering, and interactive figures. The current derivative retains the core comparison method while deliberately implementing a narrower offline workflow.

The worker invokes `clinker-v2 compare` with immutable nucleotide input, a generated feature document, an output directory, and identity cutoff (`Integration/crispr_integration/locus_compare.py:94–120`). Native comparison uses global BLOSUM62, gap opening −10 and extension −0.5, evaluates every cross-locus protein pair, and retains links meeting the cutoff (`tools/clinker-v2/clinker/bounded.py:169–199`). Identity is identical residues divided by alignment length; similarity additionally counts the defined residue groups, not a functional probability (`clinker/align.py:111–134`). The cutoff defaults to 0.3. Public tool options expose no user flags; identity and paths are worker-managed (`frontend/src/contracts/tool-options-v1.json:764–781`). Upstream API/CLI options must not be presented as supported web options.

The essential full-neighborhood requirement is met: the adapter consumes every `proteins.jsonl` row, without an `is_cas` filter, preserving coordinates, strand, phase, genetic code, partial flags, and translation (`Integration/crispr_integration/locus_compare.py:9–36,67–93`). The existing interface gate checks source/run binding, manifest hashes and row counts (`Integration/crispr_integration/annotations.py:71–105`). Translation is then checked against oriented source DNA (`locus_compare_validation.py:140–179`). Backend validation independently reconstructs the feature document from retained all-CDS evidence and immutable inputs, without importing Integration validation (`backend/src/crispr_web/execution/validation_locus_compare.py:354–460`). “All called CDSs” is not proof that every biological gene was recovered.

The bounded path does not call native homology grouping, synteny scoring, Ward ordering, or clustermap rendering. These remain available in the scientific source (`clinker/align.py:423,532,599`) but are not current web results. The frontend accurately labels similarity links and separately scaled source-forward gene maps (`frontend/src/components/results/comparison/LocusCompareResults.vue:35–46`). Optional grouping/ordering deserves evaluated feature work, not an automatic correctness repair. Similarity links establish neither orthology, function, nor a phylogeny.

## 2. Required or beneficial data — pass, with explicit locus preconditions

No missing clinker reference collection was found. BLOSUM62 is packaged with the pinned dependency; clinker needs user-selected comparative loci and CDS evidence, not a downloaded organism database (`bounded.py:169–170`; `scripts/runtime/context_tools.py:200–218`). More unrelated loci would increase computation without establishing biological comparability. A future curated comparison panel would need accession/version identity, compatible annotation and translation policy, relevant taxonomic/locus scope, and an explicit selection rationale; it is optional scientific input, not a prerequisite repair.

Admission requires 2–8 DNA records of at most 50,000 nt each (`backend/src/crispr_web/service.py:154–169`). Native limits additionally require at most 120 genes overall, 3,000 aa per protein, 6,000 cross-locus pairs, and 250 million alignment cells. CDS intervals must be linear and fully contained; origin-spanning loci need explicitly prepared linear windows (`tools/clinker-v2/CRISPRLOCI.md:17–37`). The adapter treats each submitted record as the entire locus, rather than selecting a Cas-centered region. Users must therefore select related windows and meaningful boundaries; neither sequence admission nor a similarity link proves relatedness. Short records with no called genes and comparisons with no qualifying links are valid negatives, not evidence of biological absence outside those windows.

One conditional interface limitation needs evaluation. Existing backend documentation permits Pyrodigal normalization of non-ACGT symbols to N (`validation_annotations.py:168–176`), whereas clinker feature verification translates exact IUPAC input. A fresh synthetic caller-shaped row with protein `MX` from normalized `ATGAANTAA` is rejected against original `ATGAARTAA`, whose exact translation is `MK`. This is fail-closed compatibility evidence, not an observed complete-pipeline failure: the retained 40-kb, 42-CDS ambiguity fixture had zero such mismatches and passed feature construction. Do not silently replace uncertain proteins or treat X as an unrestricted wildcard. Any remedy needs explicit original-versus-analyzed sequence policy and provenance across the contracts; no excluded tool was executed or audited.

## 3. Compact scientific output — pass under the existing v1 contract

The browser summary strips protein strings and gapped strings, caps links at 100, and explicitly marks preview truncation (`backend/src/crispr_web/summaries/locus_compare.py:44–61`). Protected detailed exports retain source hashes, complete CDS evidence, actual alignments and metrics, plus separate coordinate-only Cas context (`summaries/locus_compare.py:6–40`; `publication/locus_compare.py:9–58`). The compact projector retains essentially that complete report (`publication/compact/locus_compare.py:4–9`).

The council initially challenged this duplication as excessive compact output. The coordinating chair supplied decisive counterevidence: `docs/module-results.md:59` expressly promises protein neighborhoods and native alignments; lines 27–30 make the field meanings authoritative. Moreover, `docs/schemas/module-result-v1.json:1387–1405` requires tool/options/limits/work counts. All three members withdrew the claim that retaining these fields is a demonstrated defect. Generic compactness guidance at `docs/module-results.md:88–94` does not justify silently removing module-specific v1 evidence.

A fresh tiny native report measured 3,901 bytes as detailed JSON and 4,218 bytes as `result.json`. A hypothetical projection replacing proteins with lengths and omitting gapped strings measured 4,062 bytes: only 156 bytes, or 3.7%, saved in this case. This is not a scaling benchmark. If consumer needs justify a lighter contract, evaluate representative dense comparisons and version the change; retain all identities, scientific metrics, coordinates, strand/code/phase/partial flags, hashes, uncertainty and access to full artifacts. Current v1 completeness remains intentional. Size failures produce an explicit incomplete compact export rather than silent row loss (`publication/module_result.py:66–99`).

## 4. Downstream readiness — qualified pass; one demonstrated export defect

Detailed JSON and reconstructed protein FASTA support external protein work. Native `loci.gbk` exists but is deliberately excluded from public publication (`bounded.py:215–228`; `backend/src/crispr_web/publication/contracts.py:10,59–62`). A sanitized, independently checked GenBank export could improve external visualization, but its absence is not lost evidence: checked coordinates/translations plus original DNA remain available.

The internal port is nucleotide `target`, not a protein or annotated-locus contract (`backend/src/crispr_web/exchange.py:18–38,77–93`). `input-sequences.json` replays submitted sequences (`publication/sequence_ports.py:90–105`); `result.json` is evidence, not submission input. Frontend handoffs correctly choose sequence artifacts and revalidate input (`frontend/src/features/results/useSequenceHandoff.js:17–26,64–70`). A target replay may still require locus selection and at least two eligible records before clinker admission. No automatic path should turn similarity links into ortholog selection, RNA-family membership, or acquisition orientation.

**Confirmed defect:** both TSV writers escape valid leading alignment gaps as spreadsheet formulas. A fresh native comparison of source-bound proteins A×25 and M+A×25 produced `aligned_query=-AAAAAAAAAAAAAAAAAAAAAAAAA`, identity 25/26 and score 90. Both independent report validators accepted it. Native TSV (`bounded.py:205–211`) and reconstructed public TSV (`publication/locus_compare.py:38–44`) prepended an apostrophe; JSON remained exact. This concerns alignment strings, not strand enums: this TSV has no strand column.

The immediate platform repair is a narrow exemption for `aligned_query` and `aligned_target` after validating their restricted residue/gap alphabet. Arbitrary identifiers must retain spreadsheet protection. The native writer has the same issue and needs a separately versioned scientific-source correction; the public exporter can be repaired independently. Neither repair changes alignment science.

## Council challenges, priorities and acceptance

The methods member challenged treating absent clustering as defective integration; the data member rebutted with the derivative’s bounded scope and current UI promises. Resolution: preserve the current scientifically honest subset and evaluate grouping/order/figures separately. The chair challenged report validators’ inability to prove optimality or detect omitted qualifying links. Members confirmed arithmetic/source checks do not establish those properties, while native code exhaustively iterates pairs. No native missing-link failure was demonstrated; pinned execution and native regression controls are the appropriate trust boundary, not routine backend re-execution of the scientific engine.

Priority 1 is the demonstrated public TSV correction. Acceptance requires parsed alignment fields to equal canonical validated JSON byte-for-byte for leading gaps, retained formula protection on arbitrary labels, numeric scores remaining numeric, and continued rejection of forged alignments by both gates. A native-writer correction needs its own source/release checks. Preserve process isolation, bounded reads, cancellation, immutable input binding and capability-protected exports.

Priority 2 is an explicit interface test/documentation decision for ambiguous caller-normalized DNA; require a real interface case before generalizing prevalence and evaluate any scientific policy change separately. Optional compact redesign, GenBank publication, typed protein/locus ports and upstream synteny visualization need versioned contracts and consumer/scientific evaluation. None blocks the narrow TSV repair, and no missing reference download blocks this module.
