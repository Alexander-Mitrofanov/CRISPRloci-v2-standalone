## 1. Author-intended integration

**Verdict: properly integrated for the pinned context-extraction capability; original scientific leader prediction is unavailable, so full original-method parity does not pass.** This distinction is essential. The original authors describe repeat-guided conservation analysis that annotates orientation and conserved leader-core boundaries, with 195 reference clusters. The current server does not provide that scientific method. [Alkhnbashi et al., 2016](https://pubmed.ncbi.nlm.nih.gov/27587677/).

The native v2 implementation explicitly separates these tasks. `tools/CRISPRleader-v2/src/crisprleader/pipeline.py:15` extracts adjacent windows and emits `analysis_mode=context_extraction`, empty predictions and a null reference. Its `predict` function at line 54 always raises an actionable error because inference policy, a default biological bundle and independent evaluation remain incomplete. `tools/CRISPRleader-v2/docs/CONTRACT.md:94` declares precisely this implemented subset.

The adapter invokes the available `adapt identify`, `extract`, and `validate` commands, in that order, through the configured isolated executable (`Integration/crispr_integration/leader.py:52`). It checks the result checksum and rejects a prediction-mode response, nonempty predictions, a reference, incorrect window length, or an incorrect candidate count (`:75`). For standalone leader jobs, Identify supplies arrays; for the locus workflow, existing source-bound Identify reports are reused (`:20`). Separate environment provisioning includes CRISPRleader (`scripts/provision_tools.py:292`). No reference or executable update occurs inside this stage.

The backend independently reconstructs accepted arrays, terminal-repeat anchors and both candidate sequences from submitted DNA rather than importing the Integration validator (`backend/src/crispr_web/execution/validation_leader.py:25`, `:91`, `:136`). It validates source hashes, manifest identity, native/public source mappings, coordinates, complete array/candidate identity and counts. Twenty mutation cases in `backend/tests/test_leader.py:134` cover forged sequence, coordinates, strand, anchor, metadata, prediction claims, duplicate/omitted candidates, manifest changes and symlinks.

No demonstrated error in flank execution, source binding or strand conversion was found. The unsupported scientific capability must remain visible; passing extraction checks cannot establish that a biological leader was found.

## 2. Required data and beneficial larger datasets

**Verdict: no background dataset is missing for extraction. Biological prediction lacks both an implemented method and a validated default reference bundle.** The extractor reads source sequences and array geometry only. Adding a database cannot repair or activate the absent predictor. The outstanding requirements are explicit in `tools/CRISPRleader-v2/docs/STATUS.md:19` and are consistent with the approved improvement plan.

A worthwhile future research source is the 2025 survey of 37,477 CRISPR arrays. Taxonomy/subtype grouping yielded 87 motifs; the global analysis found no universally conserved motif. Fourteen had biochemically demonstrated roles. This is evidence for scoped reference development, not a ready prediction bundle or universal boundary labels. [Buyukyoruk et al., 2025](https://journals.sagepub.com/doi/10.1089/crispr.2024.0093).

Before adoption, a maintainer must establish asset-specific reuse terms, immutable sequence/model identities, compatible formats, taxonomy/subtype applicability and the meaning of each label. This council verified the publication's claims but did not download supplements, establish redistribution permission, or measure performance. The older improvement audit recorded 193 legacy HMM/FASTA pairs versus the paper's 195 clusters, plus unresolved reuse terms; that historical inventory must be reconciled before treating it as a complete reference release (`improvenments/CRISPRleader-v2/EVIDENCE.md:39`). It is not fresh evidence that two particular models are missing today.

The existing data-only container provides a useful engineering foundation: family identities, source/rights provenance, boundary meanings, training-locus IDs, calibration metadata and member hashes (`tools/CRISPRleader-v2/src/crisprleader/data/REFERENCE_SCHEMA.md:18`). Its checksum validation does not establish scientific quality. Container bounds of 4,096 families, 256 motifs and 256 MiB also make compatibility and memory accounting relevant (`:13`). More references increase retrieval/scanning cost and multiple-testing scope; closely related additions can inflate apparent coverage without increasing independent evidence.

A future evaluated bundle should favor reviewed family coverage over raw size, separate lineage/family holdouts from development and calibration, retain unsupported-family abstentions, and measure supported-side accuracy, false calls and coverage. Conserved-core endpoint error requires independent labels with the same boundary meaning. Extracted windows, motif matches and junction experiments cannot supply full-leader truth. These requirements already appear in `tools/CRISPRleader-v2/benchmarks/GATES.md:13`, `:34` and `:50`; their biological gates remain unevaluated.

## 3. Compact, scientific output

**Verdict: generally strong and appropriately restrained, with one demonstrated TSV interoperability defect.** The UI presents counts and intervals, defers sequences behind expandable details, distinguishes missing values from empty clipped windows, and clearly says that neither side is selected (`frontend/src/components/results/annotations/LeaderResults.vue:26`, `:45`, `:85`, `:103`). Its coordinate/orientation explanation is scientifically necessary: right windows are reverse complemented to point toward the adjacent repeat; this is not inferred transcription direction.

The full JSON summary retains source IDs/hashes, topology, array identity, categories, segments, oriented context and observed terminal-repeat sequence (`backend/src/crispr_web/summaries/leader.py:16`). Compact `result.json` projects those scientific fields, de-duplicates arrays, and includes `prediction_performed=false` and explicit analysis-window semantics (`backend/src/crispr_web/publication/compact/annotations.py:50`). Native metadata and repeated original Identify reports are excluded. Bounded previews are distinguished from complete exports; empty flanks remain in JSON/TSV and are omitted from FASTA/BED/GFF features.

The public TSV writer applies spreadsheet-formula shielding to every string beginning with `=`, `+`, `-` or `@`, including the controlled strand enum (`backend/src/crispr_web/publication/leader.py:72`). A fresh fixture-derived export produced JSON/GFF/BED strands `+` and `-`, but TSV fields `'+` and `'-`. A conventional reader comparing `strand == '-'` therefore fails. This is a small format-compatibility problem, not corruption of the native scientific evidence. The coordinate column is already explicit (`segments_0based_half_open`, `:44`); sequence orientation is documented in the UI and integration guide.

The safe correction is to preserve exact validated `+`/`-` values only in the strand column while retaining protection for arbitrary labels. Do not remove spreadsheet shielding globally or remove essential no-prediction explanations as clutter.

## 4. Downstream readiness

**Verdict: ready as source-bound context evidence; no selected leader or automatic biological consumer is available.** JSON, FASTA, GFF3 and BED carry useful sequences/intervals for external analysis. JSON/BED use zero-based half-open source-forward intervals; GFF3 converts to one-based inclusive coordinates. The separate strand specifies the sequence frame. Actual terminal repeats are retained, which matters for a future junction-aware model.

Native circular arcs are implemented and tested. The server deliberately requires unknown topology (`backend/src/crispr_web/execution/validation_leader.py:245`), because uploaded FASTA does not assert circularity; it clips at contig edges. The native Identify adapter accepts only explicitly bound topology evidence and rejects unsupported joined-origin arrays (`tools/CRISPRleader-v2/src/crisprleader/adapters/identify.py:70`). This disclosed scope limit is preferable to invented wrapping. Any future public circular workflow needs an explicit topology/provenance contract, source reconstruction and wrapped-feature tests across the entire validation chain.

Leader jobs also publish verified Identify-derived arrays, repeats and spacers (`backend/src/crispr_web/publication/sequence_ports.py:115`). Those ports can serve their existing consumers but are upstream array evidence, not leader-derived findings. `input-sequences.json` replays submitted sequences (`:90`); compact `result.json` is an evidence document, not a submission port. No current consumer requires a predicted leader. Arbitrary left/right windows must not be submitted as a homologous RNA family or used to manufacture orientation evidence. A new flank port should await an actual consumer with matching biological and coordinate requirements.

## Council challenge and resolution

The scientific reviewer challenged any broad “properly integrated” verdict: the original paper's conserved-core prediction is absent. The output reviewer rebutted that absent prediction does not make the available extraction command broken. The chair adopted the split verdict above.

The output reviewer proposed investigating the larger 2025 corpus. The scientific reviewer challenged the implication that its motifs supply universal leader labels or a compatible bundle. Both agreed that source rights, family scope, calibration and independent boundary labels remain unresolved; no download or automatic model activation is justified by dataset size alone.

The chair challenged whether lacking a flank submission port makes downstream integration defective. Both specialists identified existing evidence exports and upstream typed ports, but no justified automatic flank consumer. They also rejected enabling circularity from plain FASTA merely because the native tool supports it.

Finally, the chair challenged the TSV finding against intentional spreadsheet defense. Both specialists confirmed the exact exported discrepancy and narrowed the proposed correction to the trusted strand enum, preserving untrusted-text shielding. There was no unresolved factual disagreement after this round; scientific prediction remains an explicitly incomplete capability.
