# Repeat-derived subtype evidence

The `repeat_type` mode consumes DNA repeat FASTA or a complete `repeats.json`
sequence-set exported by detection. Up to 1000 occurrences of 1–200 bases are
accepted. The API queues work; the isolated worker invokes the separately published
[RepeatTyper 2.0.1](https://github.com/Alexander-Mitrofanov/RepeatTyper/tree/d55ebf535f21591d44a0229fd809795ddc330cda)
repository pinned in `tools/tools.lock.json`.

RepeatTyper was refactored and published before this integration. It preserves
CRISPRCasTyper 1.9.0's original model, exact canonical 4-mer/GC/length features,
exclusive prediction iteration range `(0, 41)`, and 37-class vocabulary. No model
retraining or full CRISPRCasTyper detection occurs. Original MIT attribution,
citation, upstream commit and model checksums accompany the standalone package.

```json
{
  "mode": "repeat_type",
  "sequence": ">copy1\nAACTCCCTAGGAGGGAGTAGAAG\n>ambiguous\nACGTNNNN\n",
  "tool_options": {"repeattyper": {"--threshold": 0.75}}
}
```

Predictions contain `winner`, `native_score`, `prediction` and `status`. Scores
are native closed-set model outputs, **not calibrated biological confidence**.
Below the chosen threshold, status is `uncertain` and prediction stays null;
the original winner/score remain visible. Ambiguous IUPAC inputs are `unsupported`
with null prediction, winner and score. An unfamiliar family can receive a high
score. Canonical k-mers do not infer orientation. Repeat-derived evidence must
remain separate from protein-based Cas classification and historical CRISPRmap
annotations; disagreements are meaningful, not automatically reconciled.

Every input occurrence is retained. Identical sequences are classified once and
projected onto each occurrence ID. `input-sequences.json` preserves array/source
origin metadata; compact `result.json` joins that origin onto each result. A
bounded browser preview and complete `repeat-typing.json` retain model identities, vocabulary, threshold and missing values. The flat `repeat-typing.tsv` contains per-occurrence calls, scores, status and reason; origin and model provenance remain in the JSON artifacts.
Native `repeat-type/report.json` and `predictions.tsv` remain in private worker
storage, never directly published. Public files use independently validated,
allowlisted projections and existing capability-protected downloads.

Integration checks count, identity, echoed sequence/hash, vocabulary, finite
score bounds, duplicate consistency, uncertainty and immutable model provenance.
The backend independently repeats these checks without importing Integration or
scientific-tool validators. It binds results to the original normalized inputs
and requested threshold. It does not rerun model inference during publication.

## Provisioning and release checks

Only operators provision tools, outside running jobs. `scripts/provision_tools.py`
exports the exact Git commit and installs `requirements.lock` into a dedicated
CPU-only environment. No model/reference downloads occur in a job. The mode is
advertised and accepted only when its scientific source is present in the release
manifest. Manifest schema 7.0.0 includes RepeatTyper; earlier schemas remain valid.
The source tree/model bytes and environment are covered by existing release receipts.

Standalone upstream-equivalence tests compare exact labels and native scores on
frozen upstream examples, 100 seeded random valid sequences (1–200 bases), and
reverse complements. This establishes computational preservation, not independent
biological performance. HTTP-worker tests execute the installed wheel, submit a
detection repeat handoff, verify origin-preserving results and authenticated
JSON/TSV/ZIP downloads, and reject tampered outputs. Run these with
`REPEAT_TYPER_EXECUTABLE=/absolute/path/to/repeattyper scripts/check.sh`.
Without an installed isolated executable only the real execution tests are skipped.

`frontend/scripts/browser_repeat_type.py` exercises advertisement, bounds,
submission, predicted/uncertain/unsupported rows, filtering, recovery, protected
downloads and mobile layout against an intercepted API fixture generated by the
actual classifier. `scripts/gate_release.py` adds native RepeatTyper controls for
operator-built candidate releases. This change does not activate a runtime or
deploy a service.

## Verification recorded 10 October 2026

The final full `scripts/check.sh` run passed 735 Python tests (one unrelated
pre-existing skip), 248 frontend tests, Ruff, frontend source boundaries,
production build and private-data/public-export scans. A subsequent focused run
passed 34 runtime/manifest tests, including the newly added check that a
RepeatTyper release need not include unrelated optional tools. The actual
RepeatTyper wheel ran through HTTP submission, queue, worker, independent
validation and authenticated downloads. Final backend 2.8.0 and Integration
0.10.0 wheels were built and inspected; an extracted-wheel smoke run verified
four occurrences in deliberately nonalphabetical order, including a duplicate,
an uncertain short repeat and unsupported ambiguous DNA.

Browser acceptance passed at desktop and 390px width using intercepted API
responses derived from a real classifier fixture. This is separate from the
real HTTP-worker scientific test. The existing immutable multi-tool runtime was
not rebuilt or activated: available disk space was insufficient for a duplicate
full toolset. Operator provisioning and native release-gate fixtures are updated
and tested; a full candidate toolset build remains a deployment prerequisite.
