# Bundled-example boundary

This feature verifies the public, precomputed demonstration before it reaches
the submission UI:

- `contract.js` owns schema constants and small validation predicates.
- `newick.js` validates the bounded tree grammar used by the snapshot.
- `reconstruction.js` cross-checks trees, node states, and reported metrics.
- `snapshot.js` validates public metadata, privacy rules, and teaching claims.
- `input.js` binds the snapshot to the exact masked FASTA bytes.
- `catalogue.js` covers all public analysis modes and the RNA/Type V variants,
  and compares every submitted option with the recorded request.
- `moduleSnapshot.js` validates the general, independent-run example contract.

`public/examples/` contains real pinned-tool results, generated by
`scripts/generate_examples.py` in the private parent workspace. Each input is
run twice through independent isolated worker jobs before its result is saved.
Only execution durations may differ. The legacy masked teaching snapshot keeps
its stricter validation for compatibility. Examples and live jobs share the same
result components and headings; the example notice is outside those components.

Keep validators framework-neutral and fail closed. UI components should import
the stable facade at `src/example.js`, not feature internals.
