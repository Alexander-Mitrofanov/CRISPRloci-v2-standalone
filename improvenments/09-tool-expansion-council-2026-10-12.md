**CRISPRloci next tools and methods council — 12 October 2026**

Follow-up: the [literature and biological-workflow council](10-literature-workflow-council-2026-10-12.md)
retains these five but supersedes this report's ease-first delivery priority and
repeat-first RNAalifold scope. Read it for the application evidence, explicit
community benefit and completed-analysis requirements.

The recommended five additions are **RNAalifold, clinker, Phigaro, DefenseFinder's HMM workflow, and ISEScan**. Together they extend the server from detecting and comparing CRISPR components to examining conserved RNA structure, locus organization, mobile-element context and surrounding immunity. RNAalifold is a new comparative method using the existing ViennaRNA dependency; the other four are additional software integrations.

This follows the [10 October council](07-tool-expansion-council-2026-10-10.md). Its three recommendations—RepeatTyper, SpacePHARER and CCTK—are now integrated and are not counted again. The current [lock](../tools/tools.lock.json) contains twelve scientific tools, while the [overview](../README.md) describes fifteen analysis modes. This assessment concerns local source capabilities, not verification of a deployed release.

Three specialist agents investigated target/mobile-element biology, locus/RNA/defense biology, and comparative analysis/integration. They independently researched candidates and then challenged the combined shortlist. All supported these five after discussion, with different preferences for ordering. The coordinator favors RNAalifold first for ease, clinker for direct comparative value, then Phigaro and DefenseFinder, with ISEScan conditional on resolving a dependency discrepancy. Effort labels below are engineering judgments, not measured delivery times. No candidate integration or biological benchmark was run.

| Addition | Question added to the server | Reuse of current work | Relative integration effort |
| --- | --- | --- | --- |
| **RNAalifold** | Do related repeats support a common RNA structure? | Repeat occurrences, CRISPRrepeat folds, MAFFT and ViennaRNA | Low–medium: existing engine; new family/alignment contract |
| **clinker** | How do Cas genes and neighboring genes differ between loci? | Complete native CasAndra CDS/protein evidence; array/Cas coordinates; CCTK comparisons | Low–medium: validated feature export and bounded locus windows |
| **Phigaro** | Does a locus or target match overlap a candidate prophage? | Original genomic DNA, CRISPRspacer target coordinates and locus annotations | Medium: local marker bundle, interval adapter and overlap reporting |
| **DefenseFinder** | Which other defense systems accompany this CRISPR locus? | Original DNA or complete ordered CasAndra protein evidence | Medium: immutable models and protein-to-coordinate mapping |
| **ISEScan** | Are insertion elements near or overlapping CRISPR features? | Original DNA, array/Cas/RNA intervals and comparative views | Medium, conditional: older dependencies and detailed boundary semantics |

“Easy” here means a bounded CPU workflow with reusable inputs and no need to train a new model or operate a remote analysis service. None is already a complete public workflow. Whole bacterial genomes also exceed the current default 2 Mb total-input limit in many cases; a future genome-wide mode needs measured capacity changes or an explicit partial-sequence scope. The defaults are in [backend configuration](../backend/src/crispr_web/config.py), not evidence of current production settings.

**1. RNAalifold adds comparative structure to the repeat workflow**

The current repeat analyses fold individual sequences and evaluate local array context. RNAalifold instead predicts a consensus structure from an alignment of related RNAs, combining averaged thermodynamic terms with sequence-covariation terms. Its partition-function calculation also supplies base-pair probabilities. This is a distinct question: whether a proposed structural core persists across sequence variants. [Method paper](https://doi.org/10.1186/1471-2105-9-474), [official tutorial](https://www.tbi.univie.ac.at/RNA/ViennaRNA/doc/html/tutorial/RNAalifold.html).

The first workflow should be selected repeat families: `repeats.json` → explicit family and orientation choices → MAFFT alignment → comparative folding → comparison with existing individual folds. Retain every occurrence in a crosswalk while avoiding implicit weighting by the number of identical repeat copies in an array. A later tracrRNA branch can reuse the same analysis, after adding a sequence export that preserves candidate-boundary uncertainty. RepeatTyper labels and CRISPRmap candidates can help users inspect selections; subtype agreement alone cannot establish homology.

The local scientific environment already has ViennaRNA 2.7.0 comparative functions in its Python binding. Its CRISPRrepeat environment does **not** have an RNAalifold executable. A versioned extension of the standalone CRISPRrepeat CLI using that binding is therefore the smallest route; validate equivalence of the exposed parameters and numerical results. Do not silently use the executable from the separate IntaRNA environment. The existing [folding code](../tools/CRISPRrepeat/src/crisprrepeat/folding.py) and [provisioning](../scripts/provision_tools.py) pin the current engine. ViennaRNA has its own attribution and redistribution conditions rather than a generic GPL label. [Exact 2.7.0 license](https://raw.githubusercontent.com/ViennaRNA/ViennaRNA/v2.7.0/COPYING).

Proposed results are the alignment, column-to-occurrence coordinate maps, transformation/orientation records, distinct-sequence and source counts, consensus dot-bracket structure, separate energy/covariance components and a bounded pairing table. Keep exported source DNA unchanged. Derived RNA conversion and reverse complementation must be explicit. Unresolved transcript orientation can produce separate hypotheses; evOr acquisition polarity does not settle transcription strand. The CLI accepts standard alignment formats and exposes machine-readable structural results suitable for this adapter. [RNAalifold manual](https://www.tbi.univie.ac.at/RNA/ViennaRNA/doc/html/man/RNAalifold.html).

A consensus fold is not a significance test, proof of processing, or a cleavage prediction. Nearly identical sequences can produce a fold without informative evolutionary variation. The first evaluation should cover related divergent repeats, duplicate-heavy inputs, incompatible families, reverse complements, gaps and alignment sensitivity. Show insufficient diversity explicitly. R-scape is a useful later statistical extension rather than a second slot in this five-tool list.

**2. clinker connects spacer comparisons to the surrounding locus**

CCTK compares observed spacer repertoires and order. Clinker compares protein sequences and gene organization across selected genomic neighborhoods. Combining them lets users distinguish a conserved Cas neighborhood with extensive spacer turnover from differences in the cassette or neighboring genes. The underlying method was developed for gene-cluster comparison and includes sequence and synteny information in its display ordering. Its ordering is not a phylogenetic reconstruction. [Primary paper](https://academic.oup.com/bioinformatics/article/37/16/2473/6103786).

The strongest new local finding is that CasAndra already retains **complete called CDS/protein evidence before Cas filtering**. Its [extraction](../tools/CasAndra/src/casandra/orf_fast.py) writes `genes.jsonl`, `proteins.faa` and `genes.gff3`, including source coordinates, nucleotide/protein hashes, genetic code and partial flags. [The native pipeline](../tools/CasAndra/src/casandra/pipeline.py) retains these files, and [Integration](../Integration/crispr_integration/annotations.py) retains native per-record results. The earlier obstacle is therefore smaller than “add a new genome annotator.”

These files are private intermediate evidence, not an existing public protein port. [Publication rules](../backend/src/crispr_web/publication/contracts.py) exclude native work subtrees and do not generally export FAA/JSONL. A new export must sanitize native paths and independently bind translations to the source CDS, strand, phase and per-gene translation table. The existing coordinate/nucleotide checks do not establish that full protein contract.

Proposed workflow: select a few corresponding loci → materialize bounded windows with complete CDS evidence → write GenBank records with explicit verified translations → run clinker with fixed worker count → normalize its session JSON and alignment table. Render those data in the server's own locus view, overlaying arrays, Cas calls and optional defense/prophage/IS tracks. Avoid its optional HTTP server and direct publication of generated HTML. Clinker supports GenBank/GFF inputs, session export and delimited alignment output; it warns that whole-genome all-against-all gene comparison scales poorly. [Official implementation and CLI](https://github.com/gamcil/clinker).

Clinker is MIT-licensed, database-free and CPU-based, using a modest Python scientific stack. [Dependencies](https://github.com/gamcil/clinker/blob/master/setup.py). Its [feature parser](https://raw.githubusercontent.com/gamcil/clinker/master/clinker/classes.py) can fall back to generic translation when explicit translations are absent, which is a reason to supply verified translations rather than merely forwarding a GFF file.

Bound the number of windows, genes and protein pairs. Preserve crop/contig edges and partial genes. Similarity links do not establish orthology, equivalent function, horizontal transfer or event timing. Evaluation should include duplicated genes, different genetic codes, reverse-strand loci, partially cropped genes and no-match comparisons. Broader locus groups must still pass the existing independent eligibility rules before entering SpacerPlacer or evOr.

**3. Phigaro gives spacer matches and loci prophage context**

Phigaro takes raw genome/metagenome assemblies and predicts prophage regions using phage protein-family evidence and genomic composition. This supplies a missing coordinate track: whether a locus, Cas gene or target match lies inside, overlaps the edge of, or lies near a candidate prophage region. It directly supports the earlier [connected target-investigation proposal](06-connected-scientific-pipelines.md). [Method paper](https://doi.org/10.1093/bioinformatics/btaa250).

The inspected project identifies version 2.4.0 and carries MIT licensing. Its CPU workflow uses Prodigal, HMMER and a local pVOG marker bundle. Provision these once as a frozen release asset. A first adapter should use Phigaro's own documented prediction path; sharing CasAndra's gene calls would require an explicit equivalence check. Native interval outputs allow a small adapter, and the optional candidate-region FASTA can be rebound to the original source sequence. [Official repository](https://github.com/bobeobibo/phigaro), [usage and outputs](https://phigaro.readthedocs.io/en/latest/usage/#output).

Proposed workflow: the same genomic DNA used for locus annotation → Phigaro → validated intervals → intersections with arrays, Cas features and CRISPRspacer target hits. Publish source hashes, normalized coordinates, supporting native evidence, model identity, region sequence and contig-edge status. Coordinates must be joined on source identity and sequence hash, not a reused contig label. A future locally supplied-target search could use the extracted regions, but current viral-reference searches do not automatically index a user's predicted prophages.

There is also a critical distinction in today's `protospacer` mode: it matches the submitted target against a historical reference-spacer collection. A match inside a predicted prophage is a reference-spacer match in that region. It becomes a same-genome candidate match only when the spacer is independently linked to that same genome. Exposing source-bound same-genome candidate matches needs the existing standalone source/supplied-target search capability, a source-bound spacer join and exclusion/annotation of CRISPR-array matches. Active biological self-targeting is not established by either kind of sequence match.

Phigaro is selected for practical fit rather than best overall detection accuracy. The September 2026 LAMBDA benchmark reports Phigaro precision 0.839, recall 0.662 and MCC 0.721 in its genome-wide evaluation, versus geNomad MCC 0.794. Its evaluation set contains 80 genomes and 380 annotated prophage locations, and the authors discuss incomplete reference annotations. These are external benchmark results, not expected CRISPRloci performance. [LAMBDA, Table 4 and evaluation methods](https://academic.oup.com/nargab/article/8/3/lqag103/8787816).

Keep outputs as candidate regions: they do not establish inducibility, exact biological boundaries, current viral taxonomy or active CRISPR targeting. Validate native coordinate conventions with source slices, negative and truncated-contig fixtures, overlapping regions and divergent hosts. A run with no detected regions must not become evidence that a genome lacks prophages.

**4. DefenseFinder places CRISPR in the surrounding immune repertoire**

DefenseFinder adds known non-CRISPR antiviral systems to the genomic context. Its HMM/system-rule workflow can show whether a CRISPR locus co-occurs with restriction–modification, abortive-infection or other defense systems, and whether those neighborhoods differ across the loci selected for clinker/CCTK comparison. The biological motivation is established by the original systematic survey of prokaryotic antiviral repertoires. [Primary paper](https://www.nature.com/articles/s41467-022-30269-9).

Use the established CPU HMM route for the first release. The v3 software also offers language-model approaches, which are outside this proposal's ease-of-integration scope. Current input support includes nucleotide FASTA and complete ordered protein sets. The shared CDS export proposed for clinker would let the server reuse all CasAndra-called proteins with exact coordinate mappings; a filtered Cas-only list is invalid for this purpose. [Official usage](https://github.com/mdmparis/defense-finder), [v3 release](https://github.com/mdmparis/defense-finder/releases/tag/v3.0.0).

The adapter must distinguish protein identifiers and order from genomic coordinates. `sys_beg`/`sys_end` name proteins; `position_hit` is an input-protein position. The lists of proteins and profiles in the system summary are independently sorted and must not be zipped together. Join through the gene table, then through the verified CDS map. Preserve replicon boundaries using supported dataset formatting or independent contig runs; unrelated contigs must not form one artificial ordered replicon. A contig-level scan gives assessed-sequence evidence, not a complete host inventory. [Native table definitions](https://raw.githubusercontent.com/mdmparis/defense-finder/master/README.md).

Expose three distinct layers: system calls, component genes and isolated HMM hits. Keep DefenseFinder's overlapping Cas evidence separate from CasAndra classifications. Compare co-occurrence descriptively; proximity does not prove cooperative immunity, and a system prediction does not prove activity.

The software and model collections use GPL-3.0 terms. Freeze executable and model identities separately, configure an operator-owned model directory, and disable job-time update/version-network behavior. The CPU stack includes MacSyFinder/HMMER-related components, Pyrodigal and pandas; a dedicated environment avoids altering current releases. [Requirements](https://raw.githubusercontent.com/mdmparis/defense-finder/master/requirements.txt), [model repository](https://github.com/mdmparis/defense-finder-models), [software license](https://github.com/mdmparis/defense-finder/blob/master/LICENSE).

Test multi-contig boundaries, reordered proteins, isolated hits versus complete calls, missing systems at fragment edges, and coordinate recovery. Validate that the frozen configuration really runs with network access disabled. Count predicted systems separately from individual profile hits.

**5. ISEScan adds insertion-element evidence to locus interpretation**

ISEScan detects insertion-sequence elements, including partial candidates and terminal inverted repeats, from genomic FASTA. Its useful CRISPR-facing output is an explicit overlap/distance relationship to arrays, Cas genes and RNA candidates. This can prioritize investigation of unusual locus architecture while providing an additional annotation track for clinker. [Primary paper](https://doi.org/10.1093/bioinformatics/btx433).

The inspected release is v1.7.3 with Apache-2.0 licensing. It ships transposase profile/sequence references and provides TSV, GFF3 and FASTA outputs. HMMER and BLAST overlap existing infrastructure; FragGeneScan, fastcluster and the vendored compiled SSW library add packaging work. [Release](https://github.com/xiezhq/ISEScan/releases/tag/v1.7.3), [usage and dependencies](https://github.com/xiezhq/ISEScan), [license](https://github.com/xiezhq/ISEScan/blob/master/LICENSE).

This is the most conditional recommendation. Upstream documentation requests FragGeneScan 1.30 or earlier and identifies a 1.31 incompatibility, while the current [Bioconda recipe](https://raw.githubusercontent.com/bioconda/bioconda-recipes/master/recipes/isescan/meta.yaml) requires 1.32 or newer. That discrepancy needs a small exact-version fixture pilot before committing to the runtime. It does not establish that all newer versions are incompatible. Do not substitute CasAndra's gene calls merely to remove a dependency without checking the effect on insertion-element detection.

Native coordinates are 1-based inclusive, but missing-ORF fields include zero coordinates and negative score sentinels. Convert these to missing values with reasons. Keep the per-copy E-value distinct from the best value across related copies; retain the native complete/partial label separately from independently recorded contig-edge status, which alone does not prove truncation. The reported strand belongs to the transposase ORF. [Output implementation](https://raw.githubusercontent.com/xiezhq/ISEScan/master/pred.py).

Proposed results are source-bound element intervals, family/model assignments, transposase evidence, terminal-repeat evidence and a relationship table distinguishing overlap from proximity. An element overlapping a predicted Cas CDS is a reason to inspect the locus, not proof that CRISPR is disabled. A nearby element does not establish the cause of spacer loss, locus movement or horizontal transfer. Missing calls do not establish an intact locus. Gate the adapter with complete/partial elements, absent ORFs, reverse strands, uncertain terminal repeats, no-hit input and fragment-edge cases.

**How these additions reinforce each other**

One shared CDS-and-interval contract would serve clinker and DefenseFinder, and coordinate joins would add Phigaro and ISEScan evidence to the same locus view. It should preserve source hashes, feature identity, coordinates, strand, transformations, partial/unknown states and method/model identity. Public exports must remove local paths and independently verify protein translations. Complete CDS evidence does not imply complete genome assembly.

The proposed connected workflows are:

| Starting evidence | Added analysis | Research outcome |
| --- | --- | --- |
| Related observed repeats | MAFFT → RNAalifold → existing individual folds | Inspect conserved structural hypotheses and incompatible variants |
| Selected loci with CasAndra CDS evidence | clinker + CCTK | Compare gene neighborhoods alongside observed spacer changes |
| Genomic target DNA and matching coordinates | Phigaro + interval joins | Inspect reference-spacer matches in candidate prophage context |
| Complete ordered protein evidence for the assessed sequence | DefenseFinder + locus joins | Compare CRISPR with neighboring predicted defense systems |
| Genomic DNA and existing locus features | ISEScan + interval joins + clinker | Inspect candidate insertion elements around unusual loci |

These outputs can contextualize SpacerPlacer/evOr histories, but neither a gene-similarity group nor an interval overlap changes the existing reconstruction eligibility or proves an evolutionary mechanism. Reconstructed ancestral spacer clusters must not inherit an extant representative's target matches without a sequence-level crosswalk.

**Alternatives considered and council decisions**

| Candidate | Why it remains outside the five |
| --- | --- |
| **R-scape / CaCoFold** | Valuable covariation significance and power analysis, but overlaps the comparative-RNA branch and needs sufficiently diverse, trustworthy alignments. Add after family selection works. Current source has BSD-3-Clause licensing; older GPL descriptions are stale. [Method](https://eddylab.org/R-scape/), [license](https://github.com/EddyRivasLab/R-scape/blob/master/LICENSE). |
| **skani** | Strong future whole-genome relatedness context for CCTK/evolution, with a simple offline CLI. Current record-based input lacks explicit assembly grouping, and default size limits constrain many genomes. Locus ANI is not organism relatedness; suppressed comparisons are not zero similarity. [Official guide](https://github.com/bluenote-1577/skani). |
| **MUMmer4** | Database-free DNA alignment is practical for local flanks, but annotated gene comparison supplies clearer immediate value. Repetitive-array alignments need reliable anchors before interpreting apparent losses. [Official implementation](https://github.com/mummer4/mummer). |
| **CheckV** | Useful quality/host-contamination annotation for selected viral references, but starts from viral sequences rather than arbitrary bacterial genomic input. Phigaro fills the current locus-context gap more directly. [Official package documentation](https://pypi.org/project/checkv/). |
| **Spacer2PAM** | Strong scientific connection, but local BLAST is insufficient for an offline service: the inspected downstream R workflow fetches target genomes through Entrez. It needs reference/coordinate/orientation redesign and appropriate independent target evidence. [Source](https://github.com/grybnicky/Spacer2PAM). |
| **geNomad** | Strong broader virus/plasmid/provirus capabilities and better MCC in the cited benchmark, but its license has explicit noncommercial/internal-use conditions that should not be assumed to cover the intended public service. Phigaro has a simpler initial licensing/dependency proposition. [License](https://github.com/apcamargo/genomad/blob/main/LICENSE). |
| **AcrFinder / AcRanker** | Anti-CRISPR hypotheses are attractive, but full neighborhood/protein inputs, overlapping detection machinery and deployment questions make these weaker immediate adapters. First establish same-genome match and mobile-element context. [AcrFinder](https://github.com/HaidYi/acrfinder), [AcRanker](https://github.com/amina01/AcRanker). |

The comparative reviewer initially favored skani's simple binary, then downgraded it after finding the assembly-contract and size-limit gaps. Clinker rose after inspection showed that complete CasAndra translations already exist privately. The RNA reviewer selected RNAalifold ahead of R-scape on integration effort, while requiring explicit diversity and orientation semantics. The target reviewer selected Phigaro over CheckV for raw-genome input fit and corrected the temptation to call historical-reference matches self-targeting. All reviewers retained ISEScan only with an explicit dependency pilot and locus-linked output.

**Recommended implementation sequence and acceptance**

Start with **RNAalifold**, while designing the common CDS/interval export. Then add **clinker**, which makes that shared evidence immediately useful. Add **Phigaro** and **DefenseFinder** as independent context tracks; prioritize either according to target-ecology versus immunity focus. Add **ISEScan** after resolving its exact dependency combination. Treat this as an implementation proposal, not authorization to modify scientific checkouts or deploy.

Each addition needs a standalone CLI path, pinned software/model/reference identity, bounded worker execution, independent Integration and backend validators, compact results, explicit no-hit/unsupported outcomes and source-bound exports. Validate biological usefulness separately from file-contract correctness. Benchmark realistic positive/negative and fragmented inputs, runtime, memory, temporary disk and cancellation before assigning service limits. A changed implementation requires `scripts/check.sh`, relevant browser flows and real-science release fixtures; production remains a separate request.

This council produced research documentation only. Existing scientific modules, tool locks and service configuration were not changed. Candidate performance and integration effort remain unmeasured; the only runtime inspection was a read-only check of existing ViennaRNA binding identity/functions. Local report links and the private-data scan passed. Application and browser tests were not run for this documentation-only update.
