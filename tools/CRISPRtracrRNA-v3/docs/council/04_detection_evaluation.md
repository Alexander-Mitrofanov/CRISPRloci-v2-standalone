## Finding corrected during review

**D1 — Conditional-control support class differed from production.** The initial `scripts/council_benchmark.py:conditional` called `candidate_evidence` and set `admission_branch`, but retained the standard presence-based `evidence_class`. Production resets that field using only `admission.supporting_model_hits` and `admission.supporting_terminator_hits`. A weak or incorrectly placed forward CM could therefore add a CM label in a conditional control without passing the experimental support gate. Admission counts themselves were unaffected.

I reported D1 to the coordinator and executor. Before any conditional run, the executor added the same support-derived class construction to the harness. I reread the corrected block and retained its file hash in the audit. **D1 is resolved on source and native-control inspection**: every admitted control's class agrees with its qualifying support fields. No scientific threshold or frozen control was changed.
